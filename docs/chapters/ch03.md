## 3.1 x86/x64 寄存器详解

### 3.1.1 通用寄存器的发展历史

x86 架构从 16 位时代演进而来，寄存器也随之扩展。理解这段历史有助于记忆寄存器的命名规则：

| 时代 | 寄存器 | 位数 |
|------|--------|------|
| 16位（8086） | AX, BX, CX, DX, SI, DI, BP, SP | 16-bit |
| 32位（80386） | EAX, EBX, ECX, EDX, ESI, EDI, EBP, ESP | 32-bit |
| 64位（AMD64） | RAX, RBX, RCX, RDX, RSI, RDI, RBP, RSP, R8~R15 | 64-bit |

!!! info "记忆技巧"
    在 64 位模式下，32 位寄存器（如 EAX）实际上是 RAX 的低 32 位。对 EAX 写入会**零扩展**高 32 位为 RAX。写入 AL 仅影响 RAX 的低 8 位，不会影响高 56 位。

### 3.1.2 通用寄存器详解（64位模式）

#### RAX — 累加寄存器（Accumulator）

```asm
; RAX = 0x1122334455667788
mov rax, 0x1122334455667788

; 写入 EAX 只影响低 32 位，高 32 位清零
mov eax, 0xDEADBEEF
; RAX = 0x00000000DEADBEEF

; 写入 AL 只影响低 8 位
mov al, 0xFF
; RAX = 0x00000000DEADBEF
```

**用途**：算术运算返回值、系统调用号（第 0x80 号中断时放入 EAX）

#### RBX — 基址寄存器（Base）

**用途**：常用于保存数据或作为第二个返回值。编译器会自由使用，但在手工优化代码中常作为数据指针。

#### RCX — 计数寄存器（Counter）

**用途**：循环计数（LOOP 指令）、位移指令的移位量、C++ `this` 指针（Microsoft x64 ABI）。

#### RDX — 数据寄存器（Data）

**用途**：配合 RAX 传递 128 位返回值（RDX:RAX）、I/O 操作、乘法/除法的高位结果。

#### RSI/RDI — 源/目标索引寄存器

**用途**：
- `MOVS` 系列指令（字符串操作）：RSI = 源，RDI = 目标
- `REP MOVSB` = 内存块拷贝
- AMD64 SysV ABI：RSI = 第一个整型参数，RDI = 第二个整型参数

#### RBP — 基址指针寄存器（Base Pointer）

**用途**：栈帧（Stack Frame）的基准地址。函数 prologue 通常：
```asm
push rbp
mov rbp, rsp        ; 建立栈帧
sub rsp, 0x20      ; 分配局部变量空间
```
在优化编译或使用 `-fomit-frame-pointer` 时可能被省略。

#### RSP — 栈指针寄存器（Stack Pointer）

**用途**：指向当前栈顶。PUSH/CALL 时自动递减，POP/RET 时自动递增。**永远不要随意修改 RSP**，否则程序将崩溃。

!!! warning "RSP 的神圣性"
    在 64 位 Windows 上，用户态代码必须保证 RSP 的最低 4 位为 0（16 字节对齐）。违反此规则会触发 `#GP`（通用保护异常）。这是因为 Windows 要求影子栈（Shadow Stack）和其他安全机制依赖对齐。

#### R8~R15 — 新增通用寄存器

| 寄存器 | SysV ABI 参数位置 | Microsoft x64 ABI 参数位置 |
|--------|------------------|----------------------------|
| R8 | 第1个整型参数 | 第1个整型参数 |
| R9 | 第2个整型参数 | 第2个整型参数 |
| R10 | 临时寄存器 | 第4个整型参数 |
| R11 | 临时寄存器 | 第3个整型参数 |
| R12-R15 | 临时寄存器（调用者保存） | 临时寄存器（调用者保存） |

### 3.1.3 特殊寄存器

#### RIP — 指令指针寄存器（Instruction Pointer）

`RIP` 指向**下一条将要执行的指令**的地址。它是 CPU 自动更新的，程序无法直接 `MOV RIP, xxx`，但可以通过 `JMP/CALL/RET` 等控制流指令修改它。

```asm
; RIP 的值示例
.text:0000000140001000  mov rax, rdx
.text:0000000140001003  add rax, 1
; 此时 RIP = 0x140001003（下一条指令的地址）
```

#### RFLAGS / EFLAGS — 标志寄存器

EFLAGS 是一个 32 位寄存器，其中各位含义如下：

| 位 | 名称 | 含义 |
|----|------|------|
| CF | 进位标志（Carry Flag） | 无符号运算溢出时置 1 |
| PF | 奇偶标志（Parity Flag） | 结果低 8 位中 1 的个数为偶数时置 1 |
| ZF | 零标志（Zero Flag） | 结果为 0 时置 1 |
| SF | 符号标志（Sign Flag） | 结果为负数（最高位为 1）时置 1 |
| OF | 溢出标志（Overflow Flag） | 有符号运算溢出时置 1 |
| DF | 方向标志（Direction Flag） | `STD`=1（递减）, `CLD`=0（递增），控制字符串操作方向 |
| IF | 中断标志（Interrupt Flag） | IF=1 允许硬件中断 |
| TF | 陷阱标志（Trap Flag） | TF=1 启用单步调试 |
| AF | 辅助进位标志（Auxiliary Carry） | BCD 运算相关 |
| IOPL | I/O 特权级别 |  |
| NT | 嵌套任务标志 |  |
| RF | 恢复标志（Resume Flag） |  |
| VM | 虚拟 8086 模式 |  |
| AC | 对齐检查标志 |  |
| VIF | 虚拟中断标志 |  |
| VIP | 虚拟中断待处理标志 |  |
| ID | CPUID 可用标志 |  |

!!! tip "实际渗透中常用的标志位"
    - **ZF**：判断结果是否为零（循环退出、条件跳转）
    - **SF/OF**：判断有符号运算结果
    - **CF**：判断无符号运算溢出、比较大小
    - **DF**：字符串操作方向，`CLD` 使其归零

#### 段寄存器（Segment Registers）

在 64 位模式下，段寄存器（CS/DS/ES/FS/GS/SS）的作用被大幅弱化，但 FS 和 GS 有特殊用途：

- **FS**（Linux）：Windows 上的 TEB/TEB32 基址 → `FS:[0x30]` = PEB
- **GS**（Windows）：Linux 上的段寄存器，用于线程本地存储（TLS）
- **GS**（Windows）：Windows x64 上 TLS 基址 → `GS:[0x60]` = PEB

```asm
; Windows x64 读取 PEB
mov rax, gs:0x60    ; GS:[0x60] = PEB (Process Environment Block)
mov rax, [rax+0x18] ; PEB+0x18 = RTL_USER_PROCESS_PARAMETERS
mov rax, [rax+0x20] ; ProcessParameters+0x20 = CommandLine
```

## 3.2 常用汇编指令详解

### 3.2.1 数据传送指令

#### MOV — 传送数据

```asm
mov rax, rbx        ; RBX → RAX（寄存器到寄存器）
mov rax, [rbx]      ; [RBX] → RAX（内存到寄存器，内存寻址）
mov [rax], rbx      ; RBX → [RAX]（寄存器到内存）
mov rax, 0x41414141 ; 立即数 → 寄存器
mov rax, qword [rbx+rcx*8+0x10]  ; 基址+变址*比例+偏移
```

!!! warning "MOV 的限制"
    - **立即数不能直接写入段寄存器**（需要通过通用寄存器中转）
    - **两个内存操作数不能同时出现**：`MOV [A], [B]` 是非法的
    - **IP/EIP/RIP 不能作为 MOV 的目标**
    - 立即数的大小必须与目标操作数匹配

#### LEA — 有效地址传送

`LEA` 是最容易混淆但最实用的指令。它**计算地址但不访问内存**：

```asm
;LEA rax, [rbx+0x10]  ; 计算 (RBX + 0x10) 的地址，存入 RAX
;                       相当于 rax = rbx + 0x10

; 常用技巧：lea rax, [rax+rax*4] 相当于 rax = rax * 5
; 常用技巧：lea rax, [rbx+rcx*8]  相当于 rax = rbx + rcx * 8

; 案例：用 LEA 做快速乘法
lea rax, [rax+rax*2]  ; RAX = RAX * 3
lea rax, [rax+rax*4]  ; RAX = RAX * 5
```

```c
// C 语言等价代码
int *p = &array[2]; // LEA 而不是 MOV，因为没有解引用
```

#### XCHG — 交换数据

```asm
xchg rax, rbx       ; 交换 RAX 和 RBX（隐含锁定总线）
xchg [mem], rax     ; 交换内存和 RAX（自动加 LOCK 前缀）
```

#### PUSH / POP — 栈操作

栈是**向下增长**的（地址递减）。`PUSH` 先递减 RSP 再写入数据：

```
初始状态:  RSP = 0x7FFE0300

push rax
         RSP -= 8 → 0x7FFE02F8
         [RSP] = RAX

pop rbx
         RBX = [RSP]
         RSP += 8 → 0x7FFE0300
```

```asm
push rax             ; RAX 入栈，RSP -= 8
push 0x41414141      ; 立即数入栈（编译器会编码为 push r32 imm）
push rbx             ; RBX 入栈
pushfq              ; RFLAGS 入栈（保存标志位）
call func           ; CALL 自动 PUSH 返回地址
ret                 ; POP 返回地址到 RIP

; 函数 prologue/epilogue 示例
push rbp
mov rbp, rsp
sub rsp, 0x20       ; 分配 32 字节局部变量空间
; ... 函数体 ...
mov rsp, rbp
pop rbp
ret
```

### 3.2.2 算术运算指令

#### ADD / SUB — 加减

```asm
add rax, rbx         ; RAX = RAX + RBX
add rax, 5           ; RAX = RAX + 5
sub rax, rbx         ; RAX = RAX - RBX

; 影响标志位: CF, OF, SF, ZF, AF, PF
```

#### INC / DEC — 增一减一

```asm
inc rax              ; RAX++
dec rax              ; RAX--
```

!!! note "INC/DEC 的特殊性"
    `INC` 和 `DEC` **不影响 CF 标志位**，但影响 OF、SF、ZF、AF、PF。这在循环中常用，但做无符号比较时要小心。

#### MUL / IMUL — 乘法

```asm
; 无符号乘法
mul rbx              ; RDX:RAX = RAX * RBX（128位结果）
mul bl               ; AX = AL * BL（8位）

; 有符号乘法
imul rbx             ; RDX:RAX = RAX * RBX（128位结果）
imul rcx, rdx, 5     ; RCX = RDX * 5（三操作数形式，x86新增）
```

#### DIV / IDIV — 除法

```asm
; 无符号除法
mov rax, 100         ; 被除数放入 RAX
mov rcx, 3           ; 除数
xor rdx, rdx         ; RDX 必须清零（被除数高128位）
div rcx              ; RAX = 100/3 = 33, RDX = 100%3 = 1

; 有符号除法
mov rax, -100
mov rcx, 3
idiv rcx             ; RAX = -100/3 = -33, RDX = -100%3 = -1
```

!!! warning "除零错误"
    除数为零时 CPU 触发 `#DE`（除法错误异常），会导致程序崩溃。这是 DoS 漏洞的常见来源。

### 3.2.3 比较与跳转指令

#### CMP — 比较

`CMP A, B` 实际上执行 `A - B`，**仅设置标志位，不保存结果**：

```asm
cmp rax, rbx         ; RAX - RBX，设置标志位
; 根据结果:
;   ZF=1 → RAX == RBX
;   ZF=0 → RAX != RBX
;   SF=OF → RAX >= RBX（有符号）
;   CF=0  → RAX >= RBX（无符号）
;   SF!=OF → RAX < RBX（有符号）
;   CF=1  → RAX < RBX（无符号）
```

#### TEST — 测试位

`TEST A, B` 执行 `A AND B`，仅设置标志位：

```asm
test rax, rax        ; 最常用：检测 RAX 是否为零（设置 ZF）
jz  zero_label       ; 如果 RAX==0，跳转

test rax, 1          ; 检测 RAX 最低位是否为 1
jnz odd_label        ; 如果为奇数，跳转

; 判断指针是否为 NULL
test rdx, rdx
jz  null_pointer
```

#### 条件跳转指令汇总

| 指令 | 含义 | 有符号 | 无符号 |
|------|------|--------|--------|
| `JE` / `JZ` | 等于/为零跳转 | ✓ | ✓ |
| `JNE` / `JNZ` | 不等于/非零跳转 | ✓ | ✓ |
| `JL` / `JNGE` | 小于（<）跳转 | ✓ | |
| `JLE` / `JNG` | 小于等于（≤）跳转 | ✓ | |
| `JG` / `JNLE` | 大于（>）跳转 | ✓ | |
| `JGE` / `JNL` | 大于等于（≥）跳转 | ✓ | |
| `JB` / `JNAE` | 低于（<）跳转 | | ✓ |
| `JBE` / `JNA` | 低于等于（≤）跳转 | | ✓ |
| `JA` / `JNBE` | 高于（>）跳转 | | ✓ |
| `JAE` / `JNB` | 高于等于（≥）跳转 | | ✓ |
| `JC` | 进位跳转 | | ✓ |
| `JNC` | 无进位跳转 | | ✓ |
| `JO` | 溢出跳转 | ✓ | |
| `JNO` | 无溢出跳转 | ✓ | |
| `JS` | 符号位为1跳转（负数） | ✓ | |
| `JNS` | 符号位为0跳转（非负） | ✓ | |
| `JP` | 奇偶位为1跳转（偶数个1） | | |

!!! tip "记忆方法"
    有符号用 **J**G/JL/JGE/JLE，无符号用 **J**A/JB/JAE/JBE。可以理解为 G="Greater", A="Above", L="Less", B="Below"。

### 3.2.4 控制流指令

#### CALL / RET — 函数调用与返回

```asm
; 调用函数
call 0x41414141              ; RIP = 0x41414141, PUSH 返回地址
call rax                      ; 调用 RIP 寄存器指向的地址（函数指针）

; 函数返回
ret                           ; POP 返回地址 → RIP
ret 0x10                      ; RET 后额外 ADD RSP, 0x10（清理参数）
```

**CALL 指令的实际行为**：
```asm
PUSH RIP        ; 先将返回地址（下一条指令的地址）压栈
JMP target      ; 然后跳转到目标地址
```

#### JMP — 无条件跳转

```asm
jmp label               ; 短跳（Near Jump，同一代码段内）
jmp rax                 ; 间接跳转，跳转到 RAX 保存的地址
jmp [table+rax*8]      ; 跳转表（switch-case 的汇编实现）
```

### 3.2.5 逻辑与位操作指令

```asm
and rax, rbx            ; 按位与
or  rax, rbx            ; 按位或
xor rax, rbx            ; 按位异或
not rax                 ; 按位取反
shl rax, 3              ; 左移 3 位（乘以 8）
shr rax, 3              ; 无符号右移 3 位
sar rax, 3              ; 算术右移（保留符号位，有符号除以 8）
rol rax, 4              ; 循环左移
ror rax, 4              ; 循环右移
bt  rax, 5              ; 测试第 5 位
bts rax, 5              ; 设置第 5 位
btr rax, 5              ; 复位第 5 位
```

```asm
; 常用技巧：快速清零寄存器
xor rax, rax            ; 比 mov rax, 0 更短（2字节 vs 5字节），且不依赖立即数编码
xor rdx, rdx
```

## 3.3 调用约定（Calling Conventions）

调用约定定义了**函数如何接收参数**、**谁负责清理栈**、**返回值如何传递**。这是理解二进制漏洞的关键。

### 3.3.1 cdecl（C Declaration）

**适用范围**：32位 x86 C 程序（GCC 默认）

| 规则 | 说明 |
|------|------|
| 参数传递 | 从右到左压栈 |
| 栈清理 | **调用者（caller）**负责清理参数 |
| 返回值 | EAX（32位）或 EDX:EAX（64位） |

```c
// C 代码
int sum(int a, int b, int c) {
    return a + b + c;
}
int result = sum(1, 2, 3);

// 对应汇编（调用者视角）
push 3           ; 第3个参数（最后一个压栈）
push 2           ; 第2个参数
push 1           ; 第1个参数（第一个压栈）
call sum
add esp, 12      ; ← 调用者清理栈！每个参数 4 字节，共12字节
```

```asm
; 被调用者视角（sum 函数）
push ebp
mov ebp, esp
mov eax, [ebp+8]     ; a = 第一个参数
add eax, [ebp+12]    ; eax += b
add eax, [ebp+16]    ; eax += c
mov esp, ebp
pop ebp
ret                 ; 不清理参数（调用者负责）
```

!!! note "cdecl 的优势"
    因为调用者清理栈，**可变参数函数**（如 `printf`）可以用 `cdecl`：调用者知道传了多少参数，所以 callee 可以正确解析所有参数。

### 3.3.2 stdcall

**适用范围**：32位 Windows API（Win32 API）

| 规则 | 说明 |
|------|------|
| 参数传递 | 从右到左压栈 |
| 栈清理 | **被调用者（callee）**负责清理参数 |
| 返回值 | EAX |

```asm
; 被调用者负责清理（函数末尾）
ret 12           ; = POP EIP; ADD ESP, 12 = 清理 3 个参数
```

!!! warning "stdcall vs cdecl 的安全意义"
    在漏洞分析中，注意 `ret N` 和 `ret` 的区别！如果一个函数使用 `stdcall` 但被攻击者控制，可能通过ROP（Return-Oriented Programming）利用 `ret 12` 调整栈指针。

### 3.3.3 fastcall

**适用范围**：32位程序中优化性能的关键函数（编译器实现各异）

| 规则 | 说明 |
|------|------|
| 参数传递 | 前两个参数使用 ECX、EDX（或特定寄存器） |
| 栈清理 | 被调用者清理 |

```asm
; fastcall 示例（Microsoft）
push edx           ; 第2个参数
push ecx           ; 第1个参数
call fast_func
```

### 3.3.4 x64 ABI — Microsoft x64 ABI

**适用范围**：Windows x64 程序（64位 Windows 的标准 ABI）

| 规则 | 说明 |
|------|------|
| 参数传递 | RCX, RDX, R8, R9（从左到右） |
| 额外参数 | 压栈（从右到左） |
| 栈清理 | 被调用者清理（Shadow Space 调用者建立） |
| 返回值 | RAX（128位以下）或 RDX:RAX（128位） |
| 调用者保存 | RAX, RCX, RDX, R8, R9, R10, R11 |
| 被调用者保存 | RBX, RDI, RSI, RBP, R12, R13, R14, R15 |

**Shadow Space（影子空间）**：
```asm
sub rsp, 32         ; 分配 Shadow Space（4个寄存器参数位×8字节）
mov rcx, arg1
mov rdx, arg2
mov r8,  arg3
mov r9,  arg4
call func
add rsp, 32         ; 清理 Shadow Space
```

!!! info "Shadow Space 的作用"
    1. 为被调用者提供寄存器溢出空间（spill area）
    2. 兼容 32 位调用约定
    3. Windows 安全检查的一部分（Stack Canary 放在 Shadow Space 中）

### 3.3.5 x64 ABI — System V AMD64 ABI

**适用范围**：Linux、macOS、BSD 等 Unix-like 系统的 x64 程序

| 规则 | 说明 |
|------|------|
| 参数传递 | RDI, RSI, RDX, RCX, R8, R9（从左到右） |
| 额外参数 | 压栈（从右到左） |
| 栈对齐 | 调用 `CALL` 前 RSP 必须对齐到 16 字节边界 |
| 调用者保存 | RAX, RDI, RSI, RDX, RCX, R8, R9, R10, R11 |
| 被调用者保存 | RBX, RBP, R12, R13, R14, R15 |

!!! tip "两大 x64 ABI 的对比记忆"
    - **Microsoft**：参数用 `RCX, RDX, R8, R9`（类比 C/C++ 的 `a, b, c, d`）
    - **System V**：参数用 `RDI, RSI, RDX, RCX, R8, R9`（类比 C 的 `di, si, dx, cx, r8, r9`）

### 3.3.6 调用约定对比表

| 特性 | cdecl | stdcall | fastcall | MS x64 | SysV x64 |
|------|-------|---------|----------|--------|----------|
| 平台 | 32位通用 | 32位 Windows | 32位优化 | 64位 Windows | 64位 Unix |
| 参数1 | [ESP+4] | [ESP+4] | ECX | RCX | RDI |
| 参数2 | [ESP+8] | [ESP+8] | EDX | RDX | RSI |
| 参数3 | [ESP+12] | [ESP+12] | stack | R8 | RDX |
| 参数4 | [ESP+16] | [ESP+16] | stack | R9 | RCX |
| 栈清理 | caller | callee | callee | callee | callee |
| 可变参数 | ✓ | ✗ | ✗ | ✗ | ✓ (SysV) |

## 3.4 C 语言内存布局

### 3.4.1 进程内存布局图解

在 32 位 Linux 系统中，一个典型的进程虚拟内存布局如下（**高地址 → 低地址**）：

```
┌─────────────────────────────────────┐ ← 0xFFFFFFFF (4GB)
│         内核空间 (Kernel)            │ 约 1GB（用户代码不可访问）
├─────────────────────────────────────┤ ← 0xC0000000
│                                     │
│  栈 (Stack) ⬇️                       │
│  - 局部变量                          │
│  - 函数参数                          │
│  - 返回地址                          │
│  - 环境变量                          │
│  - 命令行参数                        │
│                                     │
│          ↓ 增长                      │
│                                     │
├─────────────────────────────────────┤ ← 动态链接库映射区
│                                     │
│  内存映射段 (Memory Mapping Segment)│
│  - 动态链接库 (.so)                  │
│  - mmap 分配的文件                   │
│                                     │
├─────────────────────────────────────┤
│                                     │
│  堆 (Heap) ⬆️                        │
│  - malloc/new 分配                  │
│  - 动态分配的数据                    │
│                                     │
├─────────────────────────────────────┤
│  BSS (Block Started by Symbol)      │
│  - 未初始化的全局变量                │
│  - 初始化为0的全局变量               │
│  - 未初始化的 static 变量            │
├─────────────────────────────────────┤
│  数据段 (Data)                       │
│  - 已初始化的全局变量                │
│  - 已初始化的 static 变量            │
├─────────────────────────────────────┤
│  代码段 (Text/Code)                  │
│  - 程序指令 (.text)                  │

├─────────────────────────────────────┤
│  保留区 / 未映射                     │
└─────────────────────────────────────┘ ← 0x00000000
```

!!! note "64 位内存布局"
    64 位 Linux 的布局类似，但地址空间大幅扩展：
    - 用户空间：0x0000000000400000 ~ 0x00007FFFFFFFFFFF（约 128TB）
    - 内核空间：0xFFFF800000000000 ~ 0xFFFFFFFFFFFFFFFF（约 128TB）

### 3.4.2 各段详解

#### 代码段（.text）

```c
int add(int a, int b) {
    return a + b;
}

int main() {
    return add(1, 2);
}
```

```asm
; 反汇编代码段
.text:0000000000401060  add proc near
.text:0000000000401060                  lea eax, [rdi+rsi]
.text:0000000000401063                  retn
.text:0000000000401063  add endp

.text:0000000000401064  main proc near
.text:0000000000401064                  mov eax, 3
.text:0000000000401069                  retn
.text:0000000000401069  main endp
```

- **只读**（不可修改），修改会触发 `#PF`（页面错误）或 SIGSEGV
- 代码段通常与 `.rodata`（只读数据）相邻
- 现代 CPU 有 **指令缓存（I-Cache）**，优化执行速度

#### 数据段（.data）

```c
int initialized_global = 42;        // 数据段（有初始值）
const char *name = "Alice";         // 数据段（指针），"Alice" 在 .rodata

int main() {
    return initialized_global;
}
```

```asm
; readelf -s 查看符号表
 Symbol Table '.dynsym' ...
  Num:    Value          Size Type    Bind   Vis      Name
    8: 0000000000404028    4 OBJECT  GLOBAL DEFAULT   24 initialized_global
```

#### BSS 段

```c
int uninitialized_global;           // BSS 段（未初始化，默认为0）
int zero_global = 0;               // BSS 段（显式初始化为0）
char buffer[256];                  // BSS 段

int main() {
    return uninitialized_global;   // 值为 0
}
```

```bash
# 查看 BSS 段大小
size a.out
# text    data     bss     dec     hex filename
#  1234     256    1024    2514     9d2 a.out
```

!!! tip "BSS 的历史"
    BSS 来自 IBM 7094 机器的 "Block Started by Symbol" 伪操作。现代链接器不会将 BSS 数据写入可执行文件，只记录大小，程序加载时由操作系统分配并清零——这是可执行文件体积优化的经典技巧。

#### 堆（Heap）

```c
#include <stdlib.h>

int main() {
    int *p1 = malloc(sizeof(int));         // 分配
    int *p2 = calloc(10, sizeof(int));     // 分配并清零
    *p1 = 100;
    p1[0] = 100;                           // 堆上数组访问
    free(p1);                              // 释放
    free(p2);
    return 0;
}
```

```asm
; malloc 的典型汇编
sub rsp, 32              ; Shadow Space
mov edi, 16              ; 参数1：分配大小
call malloc              ; RDI = 分配大小，RAX = 分配到的地址
test rax, rax            ; 检查是否为 NULL
jz  malloc_failed
mov [rax], 100           ; *p1 = 100
; ...
call free
add rsp, 32
```

**堆的增长方向**：从低地址向高地址增长（与栈相反）。

#### 栈（Stack）

```c
void func(int a, int b, int c) {
    int local1 = a;         // 栈上局部变量
    int local2 = b;
    char buffer[16];
    
    buffer[0] = 'A';
    buffer[15] = 'Z';
    return;
}
```

```asm
; func 的栈布局（x64 SysV ABI）
func:
    push rbp
    mov rbp, rsp
    sub rsp, 24             ; 分配 16 字节 buffer + 8 字节对齐

    ; 参数访问（基于 RBP）
    mov [rbp-4], edi        ; local1 = a (RDI 存入栈)
    mov [rbp-8], esi        ; local2 = b (RSI 存入栈)
    
    ; 缓冲区
    lea rax, [rbp-16]       ; buffer[0] 的地址
    mov byte [rax], 41h     ; 'A'
    mov byte [rbp-1], 5Ah   ; buffer[15] = 'Z'

    leave                   ; = mov rsp, rbp; pop rbp
    ret
```

```
func 的栈帧布局（高地址 → 低地址）：
┌────────────────────┐ ← RBP（栈帧基址）
│  保存的 RBP        │  -8
├────────────────────┤
│  local2 (int b)    │  -12
├────────────────────┤
│  local1 (int a)   │  -16
├────────────────────┤
│  buffer[15]       │  -24（栈帧底部）
│  buffer[0]        │  -39
├────────────────────┤
│  (对齐填充)        │
└────────────────────┘ ← RSP
```

## 3.5 指针与内存地址

### 3.5.1 指针基础

```c
int value = 42;
int *ptr = &value;      // ptr 存储 value 的地址

printf("value 地址: %p\n", (void*)&value);
printf("value 值:   %d\n", value);
printf("ptr 的值:   %p\n", (void*)ptr);  // 与 &value 相同
printf("*ptr 的值:  %d\n", *ptr);        // 解引用 → 42
```

```asm
; 对应汇编
lea rax, [rbp-4]       ; RAX = &value（LEA 不解引用）
mov [rbp-16], rax      ; ptr = RAX
mov rdi, rax
mov eax, [rdi]         ; eax = *ptr（解引用）
```

### 3.5.2 指针运算

```c
int arr[] = {10, 20, 30, 40, 50};
int *p = arr;                  // p 指向 arr[0]

p = p + 2;                     // p 指向 arr[2]（地址 + 2*sizeof(int)）
printf("%d\n", *p);            // 输出 30

p++;                           // p 指向 arr[3]
printf("%d\n", *p);            // 输出 40

// 指针相减
int *q = arr + 4;
ptrdiff_t diff = q - p;       // diff = 2
```

!!! note "指针算术的规则"
    指针加减 N 时，实际地址变化量 = N × sizeof(指针指向的类型)。编译器在生成汇编时会自动计算偏移：
    - `int *p + 1` → `lea rax, [rsi + rsi*2]`（假设 RSI 存储基址）
    - `char *p + 1` → `inc rax`

### 3.5.3 数组与指针的关系

```c
int arr[5] = {1, 2, 3, 4, 5};
int *p = arr;           // arr 退化为指向首元素的指针
int *q = &arr[0];      // 与上面等价

// 数组下标的指针等价形式
arr[3] == *(arr + 3) == *(p + 3) == p[3]
```

```asm
; 访问 arr[3] 的两种汇编方式

; 方式1：基址 + 偏移（直接地址计算）
mov eax, [rbp-20]       ; arr[0] 的地址已知，直接计算 arr+12

; 方式2：指针运算
mov rax, [rbp-8]       ; p = &arr[0]
mov eax, [rax+12]       ; *(p+12) = arr[3]
```

### 3.5.4 指针与结构体

```c
struct Person {
    char name[20];     // +0, 偏移 0
    int age;           // +20（4字节对齐，20 mod 4 = 0）
    double salary;     // +24（8字节对齐，24 mod 8 = 0）
};                     // 总大小: 32 字节

struct Person *p = malloc(sizeof(struct Person));
strcpy(p->name, "Alice");
p->age = 30;
p->salary = 5000.0;
```

```asm
; 访问结构体成员
lea rax, [rbp-32]      ; RAX = &p
mov rax, [rax]         ; RAX = *p（解引用）
mov dword [rax+20], 30 ; p->age = 30
movsd xmm0, [rax+24]   ; p->salary（XMM 寄存器用于浮点数）
```

## 3.6 结构体内存对齐

### 3.6.1 对齐规则

结构体对齐规则遵循以下原则：
1. 每个成员的偏移必须是其**自身大小**的倍数（2→2, 4→4, 8→8...）
2. 结构体总大小必须是**最大成员大小**的倍数

### 3.6.2 对齐示例

```c
struct Example1 {
    char a;      // +0, 大小 1 → 偏移 0
    int b;       // +4, 大小 4 → 偏移 4（需要填充 3 字节）
    char c;      // +8, 大小 1 → 偏移 8
};               // 总大小: 12（不是 6！）

struct Example2 {
    int b;       // +0, 大小 4 → 偏移 0
    char a;      // +4, 大小 1 → 偏移 4
    char c;      // +5, 大小 1 → 偏移 5
};               // 总大小: 8（比 Example1 更节省空间）
```

```
struct Example1 内存布局（12字节）：
┌────┬──────────┬────┐
│ a  │ padding  │ b  │
│ +0 │ +1~+3    │ +4 │
├────┴──────────┼────┤
│ c  │ padding  │    │
│ +8 │ +9~+11   │    │
└────┴──────────┴────┘

struct Example2 内存布局（8字节）：
┌──────────┬────┬────┐
│ b        │ a  │ c  │
│ +0       │ +4 │ +5 │
└──────────┴────┴────┘
```

!!! tip "漏洞挖掘中的结构体对齐"
    错误的结构体定义可能导致**缓冲区溢出**或**信息泄露**。分析二进制时，使用 IDA/Ghidra 自动推断的结构体布局比手动猜测更可靠。

## 3.7 ARM 汇编基础（AArch64）

### 3.7.1 为什么移动安全需要 ARM

- Android 应用运行在 ARM 处理器上
- iOS 设备使用 ARM64（AArch64）架构
- 许多 IoT 设备、网络设备使用 ARM
- 漏洞分析中经常遇到 ARM/Thumb 混合指令集

### 3.7.2 AArch64 寄存器

#### 31 个通用寄存器（X0~X30 / W0~W30）

| 寄存器 | 别名 | 用途 |
|--------|------|------|
| X0~X7 | — | 参数传递（前8个整型参数），返回值 |
| X8 | — |间接返回值地址（结构体返回） |
| X9~X15 | — | 临时寄存器（caller-saved） |
| X16~X17 | — | 临时寄存器（IP0, IP1，链接器使用） |
| X18 | — | 平台寄存器（平台特定，通常保留） |
| X19~X28 | — | 临时寄存器（callee-saved） |
| X29 | FP | 帧指针（Frame Pointer） |
| X30 | LR | 链接寄存器（保存返回地址，相当于 x86 的 CALL PUSH RIP） |
| X31 / SP | SP | 栈指针 |
| XZR | ZR | 零寄存器（读取为0，写入丢弃） |
| W0~W30 | — | X0~X30 的低 32 位 |

!!! note "W 寄存器的特殊性"
    W 寄存器是 X 寄存器的低 32 位。写入 W 寄存器会**零扩展**高 32 位为 X 寄存器——与 x86-64 的 EAX/RAX 行为相同。

#### 特殊寄存器

| 寄存器 | 名称 | 用途 |
|--------|------|------|
| PC | 程序计数器 | 相当于 x86 的 RIP |
| SP | 栈指针 | 指向当前栈顶 |
| FP / X29 | 帧指针 | 建立栈帧 |
| LR / X30 | 链接寄存器 | 保存返回地址 |
| NZCV | 条件标志 | 相当于 x86 的 EFLAGS（NZCV = Negative/Zero/Carry/Overflow） |
| CPSR | 当前程序状态寄存器 | 条件标志+模式位 |
| SPSR | 保存的程序状态寄存器 | 异常处理时保存 CPSR |

### 3.7.3 常用 ARM64 指令

#### 数据传送

```asm
mov x0, #42           ; X0 = 42（立即数）
mov x0, x1            ; X0 = X1
mov w0, w1            ; W0 = W1
ldr x0, [sp]          ; X0 = [SP]（加载）
str x0, [sp]         ; [SP] = X0（存储）
str x0, [sp, #8]     ; [SP+8] = X0（偏移寻址）
ldp x0, x1, [sp]     ; 加载一对（pair），用于加载两个连续寄存器
stp x0, x1, [sp]     ; 存储一对
```

#### LDP / STP（加载/存储对）

```asm
; 相当于 x86 的 PUSH POP，但更灵活
stp x29, x30, [sp, #-16]!   ; 预索引存储：SP -= 16, 然后 [SP] = X29, [SP+8] = X30
ldp x29, x30, [sp], #16     ; 后索引加载：[SP] = X29, [SP+8] = X30, SP += 16
```

#### 算术运算

```asm
add x0, x1, x2        ; X0 = X1 + X2
add x0, x1, #5        ; X0 = X1 + 5
sub x0, x1, x2        ; X0 = X1 - X2
add x0, x0, x0, lsl #2  ; X0 = X0 + (X0 << 2) = X0 * 5

; 乘法/除法
mul x0, x1, x2        ; X0 = X1 * X2
sdiv x0, x1, x2       ; X0 = X1 / X2（有符号）
udiv x0, x1, x2       ; X0 = X1 / X2（无符号）
```

#### 比较与分支

```asm
cmp x0, #0            ; X0 - 0，设置标志位
cbz x0, label         ; Compare and Branch if Zero（条件分支）
cbnz x0, label        ; Compare and Branch if Not Zero
b.eq label            ; ZF=1 时跳转
b.ne label            ; ZF=0 时跳转
b.gt label            ; 有符号大于跳转
b.lo label            ; 无符号低于跳转
bl func               ; Branch with Link = CALL func
ret                   ; RET = BR X30（跳转到 LR 指向的地址）
```

!!! note "ARM 的条件执行"
    ARM 指令集支持在大多数指令末尾添加条件后缀（`.EQ`, `.NE`, `.GT`, `.LT` 等），这称为**条件执行**。但 AArch64 移除了这一特性，改用条件分支指令。

### 3.7.4 AAPCS64 调用约定

AAPCS64（ARM Architecture Procedure Call Standard 64）是 ARM64 的标准调用约定：

| 规则 | 说明 |
|------|------|
| 参数传递 | X0~X7（前8个整型参数） |
| 返回值 | X0（整型）或 X0~X1（128位） |
| 调用者保存 | X0~X17（含参数寄存器） |
| 被调用者保存 | X19~X29, SP, LR |
| 栈对齐 | 16 字节对齐（函数入口 SP 必须 16 字节对齐） |

```asm
; ARM64 函数调用示例
; C: int add(int a, int b, int c, int d, int e)
; a=X0, b=X1, c=X2, d=X3, e=X4, f=[SP+0]

add:
    stp x29, x30, [sp, #-16]!   ; 保存 FP 和 LR
    mov x29, sp                  ; 建立栈帧
    
    add w0, w0, w1               ; w0 = w0 + w1
    add w0, w0, w2               ; w0 = w0 + w2
    add w0, w0, w3               ; w0 = w0 + w3
    ldr w1, [sp]                 ; 加载第5个参数 e
    add w0, w0, w1               ; w0 = w0 + w4
    ldp x29, x30, [sp], #16     ; 恢复栈帧
    ret                          ; RET
```

## 3.8 实战：GCC 生成汇编与反汇编

### 3.8.1 生成汇编代码（GCC -S）

```bash
# 生成 x86-64 AT&T 语法汇编
gcc -S -O0 -fno-stack-protector -masm=intel hello.c -o hello_O0.s

# 生成 x86-64 AT&T 语法汇编（优化版本）
gcc -S -O2 -fno-stack-protector -masm=intel hello.c -o hello_O2.s

# 查看差异（过滤掉注释）
diff <(grep -v '^\s*#' hello_O0.s) <(grep -v '^\s*#' hello_O2.s)
```

```c
// hello.c — 实战示例程序
#include <stdio.h>
#include <string.h>
#include <stdlib.h>

int sum_array(int *arr, int n) {
    int total = 0;
    for (int i = 0; i < n; i++) {
        total += arr[i];
    }
    return total;
}

void copy_buffer(char *dst, const char *src, size_t n) {
    for (size_t i = 0; i < n; i++) {
        dst[i] = src[i];
    }
    dst[n] = '\0';
}

int main() {
    int nums[] = {1, 2, 3, 4, 5};
    int result = sum_array(nums, 5);
    printf("Sum: %d\n", result);
    
    char buf[16];
    copy_buffer(buf, "Hello, World!", 13);
    printf("%s\n", buf);
    return 0;
}
```

**无优化版本（-O0）的关键汇编**：

```asm
sum_array:
    push    rbp
    mov     rbp, rsp
    mov     QWORD PTR [rbp-24], rdi    ; arr 参数存入栈
    mov     DWORD PTR [rbp-28], esi    ; n 参数存入栈
    mov     DWORD PTR [rbp-4], 0       ; total = 0
    mov     DWORD PTR [rbp-8], 0       ; i = 0
    jmp     .L2                        ; 跳到循环条件判断

.L3:                                       ; 循环体
    mov     eax, DWORD PTR [rbp-8]      ; eax = i
    cdqe
    mov     edx, DWORD PTR [rbp-24+rax*4] ; edx = arr[i]
    add     DWORD PTR [rbp-4], edx      ; total += arr[i]
    add     DWORD PTR [rbp-8], 1        ; i++
.L2:                                       ; 循环条件
    mov     eax, DWORD PTR [rbp-8]      ; eax = i
    cmp     eax, DWORD PTR [rbp-28]     ; 比较 i 和 n
    jl      .L3                         ; 如果 i < n，跳到循环体
    mov     eax, DWORD PTR [rbp-4]      ; 返回 total
    pop     rbp
    ret
```

**优化版本（-O2）的关键汇编**：

```asm
sum_array:
    test    esi, esi                   ; 检查 n == 0？
    mov     eax, 0                     ; 默认返回值 = 0
    je      .L2                        ; n == 0 直接返回
    xor     edx, edx                   ; edx = 0（累加器）
    lea     rsi, [rsi-1]               ; n-1
    add     rdx, QWORD PTR [rdi]       ; 加载 arr[0] 到 edx
    cmp     esi, 1                     ; n <= 1？
    je      .L5                        ; 直接返回 arr[0]
    lea     rsi, [rdi+rsi*4]           ; &arr[n-1]
    add     edx, DWORD PTR [rsi]       ; edx += arr[n-1]
    cmp     esi, 2                     ; n <= 2？
    je      .L5
    xor     eax, eax                   ; eax = 0
    lea     rdi, [rdi+4]               ; &arr[1]
    .p2align 4,,7                      ; 对齐优化
.L6:
    add     eax, DWORD PTR [rdi]       ; eax += arr[i]
    add     rdi, 4                    ; rdi += 4（下一个元素）
    cmp     rdi, rsi                   ; 比较 &arr[i] 和 &arr[n-1]
    jne     .L6                        ; 未到末尾继续循环
    add     eax, edx                   ; eax += edx
    .p2align 4,,7
.L5:
    .p2align 4,,7
.L2:
    ret
```

!!! tip "优化后的代码更难分析"
    - 循环可能被完全展开（Loop Unrolling）
    - 变量可能被完全消除（Dead Store Elimination）
    - 条件分支可能被重排
    - 使用 `-O0` 生成的代码更接近源代码，适合学习；实际漏洞分析可能需要理解优化后的行为

## 3.9 实战练习：手工分析缓冲区溢出

### 3.9.1 实验：栈缓冲区溢出

```c
// overflow_demo.c
#include <stdio.h>
#include <string.h>

void vulnerable_function(char *input) {
    char buffer[64];          // 64 字节栈缓冲区
    strcpy(buffer, input);   // 没有边界检查！
}

void win_function() {
    printf("🎯 漏洞利用成功！\n");
}

int main(int argc, char *argv[]) {
    if (argc != 2) {
        printf("用法: %s <输入字符串>\n", argv[0]);
        return 1;
    }
    vulnerable_function(argv[1]);
    printf("输入完成\n");
    return 0;
}
```

**编译（关闭保护机制）**：

```bash
gcc -g -O0 -fno-stack-protector -z execstack -no-pie -z norelro \
    overflow_demo.c -o overflow_demo
```

**溢出分析**：

```
栈帧布局（vulnerable_function）：
┌─────────────────────────────────────┐ ← RBP
│ 保存的 RBP                          │ RBP-8
├─────────────────────────────────────┤
│ 输入参数 (char *input)               │ RBP-16
├─────────────────────────────────────┤
│ buffer[0] ~ buffer[63]             │ RBP-16-64 = RBP-80
├─────────────────────────────────────┤
│ 保存的 RIP（返回地址）               │ RBP-8（由 CALL PUSH）
└─────────────────────────────────────┘ ← RSP
```

**构造溢出**：

```python
#!/usr/bin/env python3
# exploit_generator.py
import struct

# 64 字节填充 + 8 字节 RBP + 8 字节返回地址
buffer = b"A" * 64          # 填满缓冲区
buffer += b"B" * 8           # 覆盖保存的 RBP
buffer += struct.pack("<Q", 0x401156)  # win_function 的地址（小端序）

print(buffer.decode('latin-1'))
```

**执行**：

```bash
./overflow_demo "$(python3 exploit_generator.py)"
# 输出: 🎯 漏洞利用成功！
```

### 3.9.2 整数溢出在汇编层面的表现

#### 整数溢出类型 1：上溢（Wrap-around）

```c
// 整数上溢示例
#include <stdio.h>
#include <stdint.h>

void allocate_buffer(size_t size) {
    // size 是 size_t（无符号），但我们想检查是否为负数
    if (size < 0) {           // 这个检查永远不会为真！
        return;
    }
    
    char *buf = malloc(size * sizeof(char));  // size * 1 可能上溢
    if (buf) {
        printf("分配了 %zu 字节\n", size);
        // 填充操作...
        free(buf);
    }
}

int main() {
    // 当 size = -1 时（作为有符号传入）
    // size_t(-1) = 0xFFFFFFFFFFFFFFFF = 18446744073709551615
    // malloc 会分配一个巨大的内存
}
```

```asm
; 整数溢出在汇编中的表现
; 假设 size 在 EDI 中（x64 SysV）
allocate_buffer:
    movsxd rax, edi          ; 符号扩展（有符号参数）
    ; 或者：
    ; mov eax, edi           ; 直接使用（无符号）
    
    test edi, edi            ; 检查是否为 0
    je .L4
    
    ; 乘法：size * 1 不会溢出，但如果乘以 sizeof(struct)
    imul rax, rax, 32        ; RAX = size * 32
    
    ; 整数溢出发生在 imul 结果超出寄存器容量时
    ; 例如：RAX = 0x8000000000000000 * 32 → 上溢后变成一个小数
    
    mov edi, eax
    call malloc              ; malloc((size_t)(size*32))
```

#### 整数溢出类型 2：截断

```c
// 整数截断示例
#include <stdio.h>
#include <stdint.h>

void process_data(uint32_t length) {
    // 错误：将 32 位值截断为 16 位
    uint16_t short_length = length;  // 截断！
    
    char *buf = malloc(short_length + 1);  // 可能分配过小
    if (buf) {
        memset(buf, 0, short_length + 1);
        // 从网络读取 short_length 字节数据到 buf
        // ...
        free(buf);
    }
}
```

```asm
; 整数截断在汇编中的表现
process_data:
    mov eax, edi              ; EAX = 32位 length
    movzx eax, ax             ; AL = AX（截断为16位！）
    inc ax                    ; short_length + 1
    movzx edi, ax            ; 再扩展为 32 位传给 malloc
    call malloc
    
; 示例：
; length = 0x00020001 (131073)
; short_length = 0x0001 (1)   ← 截断丢失了 0x020000
; malloc(2)                    ← 分配 2 字节，但实际数据有 131073 字节！
```

#### 整数溢出类型 3：符号错误

```c
// 符号错误导致缓冲区溢出
#include <stdio.h>
#include <stdlib.h>

void allocate_array(int n) {
    // 错误：使用有符号整数进行无符号大小计算
    if (n > 0 && n < 1000) {
        char *buf = malloc(n);  // n 可能为负数（被截断为 size_t）
        // ...
    }
}

int main() {
    allocate_array(-10);  // malloc 收到一个巨大的 size_t 值
    return 0;
}
```

### 3.9.3 漏洞识别模式总结

在反编译代码中快速识别漏洞模式：

| 汇编模式 | 潜在漏洞 | 原因 |
|---------|---------|------|
| `movsb/movsw` + 无边界检查 | 缓冲区溢出 | 复制长度未验证 |
| `strcpy/strcat/sprintf` | 缓冲区溢出 | 无边界检查的字符串操作 |
| `add rsp, rax` 来自用户输入 | 栈调整攻击 | 攻击者控制栈指针 |
| `imul` 后无溢出检查 | 整数溢出 | 乘法结果可能超出预期范围 |
| `div/idiv` 前无除数检查 | 除零错误 | 导致 `#DE` 异常（DoS） |
| `call [rax]`（函数指针来自用户） | 控制流劫持 | 攻击者可能控制跳转目标 |
| 用户输入 → `jmp/call` | 控制流劫持 | ROP/JOP 攻击的基础 |

## 3.10 编译器优化对汇编的影响

### 3.10.1 常见优化级别

| 选项 | 优化内容 |
|------|---------|
| `-O0` | 无优化，接近源代码，调试友好 |
| `-O1` | 基本优化，保留调试信息 |
| `-O2` | 常用优化，代码膨胀最小化 |
| `-O3` | 激进优化（包括循环展开、向量化） |
| `-Os` | 以代码大小优先的优化 |
| `-Ofast` | 激进浮点优化（可能违反标准） |

### 3.10.2 常见优化模式

#### 1. 常量折叠（Constant Folding）

```c
int result = 100 + 200 * 3;
```

```asm
; -O0
mov eax, 100
mov edx, 200
imul edx, 3
add eax, edx

; -O2
mov eax, 700        ; 编译时直接计算 100 + 600 = 700
```

#### 2. 死代码消除（Dead Code Elimination）

```c
int unused() {
    int x = 10;     // 永远不会使用
    return 0;
}
```

```asm
; -O2
xor eax, eax        ; 直接返回 0
ret
```

#### 3. 循环展开（Loop Unrolling）

```c
for (int i = 0; i < 4; i++) {
    arr[i] = i;
}
```

```asm
; -O0: 完整的循环
; -O2: 可能展开为 4 次直接赋值
mov DWORD PTR [rax], 0
mov DWORD PTR [rax+4], 1
mov DWORD PTR [rax+8], 2
mov DWORD PTR [rax+12], 3
```

#### 4. 函数内联（Function Inlining）

```c
static inline int add(int a, int b) {
    return a + b;
}
int main() {
    return add(1, 2);
}
```

```asm
; -O2: add 函数被内联到 main
main:
    mov eax, 3     ; 直接计算 1+2=3
    ret
```

#### 5. 公共子表达式消除（CSE）

```c
int a = x + y + z;
int b = x + y + w;
```

```asm
; -O0: 两次计算 x+y
; -O2: 计算一次，存储在寄存器中复用
mov eax, [x]
add eax, [y]
mov [a], eax
add eax, [z]
mov [a], eax
mov eax, [x]
add eax, [y]
add eax, [w]
mov [b], eax
```

### 3.10.3 优化对漏洞分析的影响

!!! warning "关键警示"
    **编译器优化会改变代码布局！** 在 `-O0` 中有效的攻击方法（如精确覆盖返回地址）在 `-O2` 中可能完全失效：
    
    1. **寄存器分配优化**：局部变量从栈变为寄存器，攻击者无法通过栈操作修改它们
    2. **栈帧省略**（`-fomit-frame-pointer`）：RBP 不再指向栈帧，栈布局更难分析
    3. **函数内联**：被调用函数代码消失，分析时需要理解内联行为
    4. **尾部调用优化**（Tail Call Optimization）：`return func()` 变为 `jmp func`，不再有返回地址
    5. **SROP（伪造 ROP）** 在优化代码中更难构造，因为 gadget 减少

## 3.11 章节总结

本章我们建立了漏洞挖掘最重要的底层基础——汇编语言和内存模型。以下是核心要点回顾：

### 核心知识点

1. **x86/x64 寄存器**
   - 通用寄存器（RAX~R15）：各司其职，RAX 用于返回值和系统调用号
   - RIP（指令指针）：下一条指令地址，不可直接修改
   - RFLAGS：标志位寄存器，ZF/CF/OF/SF 是漏洞分析中最常用的标志位
   - RSP/RBP：栈操作的核心寄存器

2. **常用指令**
   - 数据传送：`MOV`、`LEA`（计算地址）、`PUSH/POP`
   - 算术：`ADD/SUB/MUL/DIV/IMUL/IDIV`
   - 控制流：`CMP/TEST` + 条件跳转、`CALL/RET`
   - 位操作：`AND/OR/XOR/NOT/SHL/SHR`

3. **调用约定**
   - 32位：cdecl（调用者清栈）、stdcall（被调用者清栈）
   - 64位：Microsoft x64（RCX/RDX/R8/R9 + Shadow Space）vs System V（RSI/RDI/RDX/RCX/R8/R9）

4. **内存布局**
   - 栈（向下增长）：局部变量、参数、返回地址
   - 堆（向上增长）：动态分配
   - BSS/Data/Text：全局变量和代码

5. **指针**
   - 指针存储地址，指针运算自动乘以类型大小
   - 数组名退化为指向首元素的指针

6. **ARM64**
   - X0~X7 传参，X30(LR) 保存返回地址
   - AArch64 调用约定 AAPCS64

7. **漏洞相关汇编**
   - 缓冲区溢出：覆盖返回地址或函数指针
   - 整数溢出：算术运算超出类型范围
   - 截断：高位数据丢失导致意外值
