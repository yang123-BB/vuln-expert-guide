## 9.1 静态分析基础

### 9.1.1 定义与优势

**静态分析**（Static Analysis）是在**不运行程序**的情况下，通过扫描源代码或二进制代码来发现漏洞的技术。

**优势**：
- ✅ 覆盖率髙（可以分析所有代码路径）
- ✅ 早期发现（开发阶段就能发现漏洞）
- ✅ 自动化程度高（可集成到 CI/CD）

**局限**：
- ❌ 误报率高（路径不可达、约束不满足）
- ❌ 无法处理动态行为（运行时生成代码、反射）
- ❌ 复杂程序分析困难（OOP、多态、回调函数）

### 9.1.2 分析流程

```
源代码/二进制 → 预处理 → 中间表示（IR）→ 分析 → 报告
```

**步骤详解**：

1. **信息收集**：
   - 源代码：AST（抽象语法树）、符号表
   - 二进制：反汇编、符号提取、字符串提取

2. **预处理**：
   - 编译（源码 → 二进制）
   - 反编译（二进制 → 伪代码）
   - 规范化（去除混淆、解密字符串）

3. **分析**：
   - 控制流分析（CFG）
   - 数据流分析（Def-Use Chain）
   - 污点分析（Taint Analysis）
   - 符号执行（Symbolic Execution）

4. **验证**：
   - 人工审核（确认漏洞真实性）
   - 动态验证（编写 PoC）

### 9.1.3 静态 vs 动态分析对比

| 维度 | 静态分析 | 动态分析 |
|------|----------|----------|
| 代码覆盖率 | 高（理论上100%） | 低（依赖输入） |
| 误报率 | 高 | 低 |
| 漏报率 | 低 | 高 |
| 运行成本 | 低（无需运行） | 高（需要执行） |
| 适用场景 | 代码审计、合规检查 | Fuzzing、调试 |

**最佳实践**：静态分析 + 动态验证（减少误报）

## 9.2 反汇编基础

### 9.2.1 线性扫描（Linear Sweep）

**原理**：从入口点开始，逐字节反汇编，不区分代码与数据。

**优势**：
- 简单快速
- 覆盖所有代码（包括混淆代码）

**劣势**：
- 误将***

**实战**：用 BinDiff 对比补丁前后二进制

### 9.5.1 BinDiff 简介

BinDiff 是 Zynamics（被 Google 收购）开发的二进制比对工具，可以识别补丁中的漏洞修复位置。

**核心功能**：
- 函数匹配（基于 CFG 相似度）
- 基本块匹配（基于指令序列）
- 算法：BinDiff 使用 **graph-theoretical** 算法

### 9.5.2 使用 BinDiff 分析 CVE 补丁

**步骤**：

1. **准备两个版本**：
   - 未补丁版本：`vuln_binary`
   - 已补丁版本：`patched_binary`

2. **用 IDA Pro 分析两个版本**：
   ```
   File → Open → vuln_binary (保存为 vuln_binary.idb)
   File → Open → patched_binary (保存为 patched_binary.idb)
   ```

3. **导出 BinDiff 文件**：
   ```
   File → Produce file → BinDiff file → vuln_binary.bin
   File → Produce file → BinDiff file → patched_binary.bin
   ```

4. **运行 BinDiff**：
   ```bash
   bindiff vuln_binary.bin patched_binary.bin
   ```

5. **查看比对结果**：
   - 相似度分数（0-1，1 表示完全相同）
   - 未匹配函数（可能是补丁新增的）
   - 相似度低的函数（可能是补丁修改的）

**实战案例**：CVE-2019-8942（struct sockaddr 类型混淆）

1. 下载补丁前后版本：
   ```bash
   wget https://example.com/v1.0.tar.gz
   wget https://example.com/v1.1.tar.gz
   ```

2. 编译两个版本：
   ```bash
   tar -xzf v1.0.tar.gz && cd v1.0 && make
   tar -xzf v1.1.tar.gz && cd v1.1 && make
   ```

3. 用 BinDiff 比对，发现 `parse_sockaddr()` 函数被修改

4. 分析修改点：
   ```c
   // v1.0（漏洞版本）
   void parse_sockaddr(struct sockaddr *addr) {
       // 没有检查 addr->sa_family
       process_address(addr->sa_data);
   }
   
   // v1.1（补丁版本）
   void parse_sockaddr(struct sockaddr *addr) {
       if (addr->sa_family != AF_INET && addr->sa_family != AF_INET6) {
           return;  // 修复：检查地址族
       }
       process_address(addr->sa_data);
   }
   ```

## 9.6 常见漏洞模式识别

### 9.6.1 危险函数列表

**C 标准库危险函数**：

| 函数 | 漏洞类型 | 安全替代 |
|------|---------|----------|
| `strcpy()` | 缓冲区溢出 | `strncpy()` |
| `strcat()` | 缓冲区溢出 | `strncat()` |
| `gets()` | 缓冲区溢出 | `fgets()` |
| `sprintf()` | 格式化字符串/溢出 | `snprintf()` |
| `scanf()` | 格式化字符串/溢出 | `scanf_s()` |
| `memcpy()` | 整数溢出 | 检查长度 |
| `malloc()` | 整数溢出 | 检查分配大小 |

**Linux 系统调用**：
- `exec*()` 系列：命令注入
- `system()`：命令注入
- `popen()`：命令注入

### 9.6.2 整数溢出模式

**原理**：整数运算结果超出类型范围，导致环绕（wrap around）。

**常见模式**：

```c
// 模式1：分配大小计算溢出
int len = user_input;
char *buf = malloc(len * 2);  // 如果 len > INT_MAX/2，溢出！

// 模式2：数组索引溢出
int index = user_input;
if (index < MAX) {
    array[index] = value;  // 如果 index 为负，绕到正数
}

// 模式3：长度检查绕过
unsigned int len = user_input;
if (len < 100) {
    char buf[100];
    memcpy(buf, input, len);  // 如果 len 为负（转为无符号会很大），溢出！
}
```

**检测工具**：
- Clang Static Analyzer：`-enable-checker security.integer`
- Coverity：整数溢出检测

### 9.6.3 格式化字符串模式

**原理**：格式字符串参数与数据参数不匹配，导致信息泄露或任意内存写入。

**危险函数**：
- `printf(fmt, ...)`
- `sprintf(buf, fmt, ...)`
- `fprintf(fp, fmt, ...)`

**漏洞代码**：
```c
char fmt[100];
fgets(fmt, sizeof(fmt), stdin);
printf(fmt);  // 危险！用户控制格式字符串
```

**利用**：
```c
// 信息泄露
printf("%p %p %p %p");  // 泄露栈内容

// 任意内存写入
printf("%n");  // 向栈上地址写入已输出字符数
```

**检测工具**：
- GCC：-Wformat-security`
- Clang：-fsanitize=format`

### 9.6.4 TOCTOU（Time-of-Check, Time-of-Use）

**原理**：检查与使用之间存在时间窗口，攻击者可以修改被检查的对象。

**典型场景**：
```c
// 漏洞代码
if (access(file, W_OK) == 0) {  // 检查文件权限
    sleep(1);  // 时间窗口
    fd = open(file, O_WRONLY);  // 攻击者可以替换文件
    write(fd, data, len);
}
```

**利用**：
1. 程序检查 `/tmp/legit_file`（属主是当前用户）
2. 攻击者将 `/tmp/legit_file` 替换为符号链接 → `/etc/shadow`
3. 程序打开符号链接，写入 `/etc/shadow`

**修复**：
- 使用 `fopen()` 打开文件，然后用 `fstat()` 检查文件元数据
- 使用 `O_NOFOLLOW` 标志（Linux）

## 9.7 实战案例：CVE-2019-8942 完整分析

### 9.7.1 漏洞背景

CVE-2019-8942 是 Linux 内核 `fs/ceph` 子系统中的一个类型混淆漏洞，允许本地攻击者提升权限。

### 9.7.2 静态分析过程

**步骤1：获取补丁**：
```bash
git clone https://github.com/ceph/ceph.git
git log --grep="CVE-2019-8942"
```

**步骤2：查看补丁差异**：
```diff
--- a/fs/ceph/inode.c
+++ b/fs/ceph/inode.c
@@ -456,6 +456,9 @@ static int ceph_fill_inode(struct inode *inode,
     struct ceph_inode_info *ci = ceph_inode(inode);
     struct ceph_inode_layout *layout = &ci->i_layout;
     
+    if (le32_to_cpu(info->layout.fl_stripe_unit) == 0)
+        return -EINVAL;
+        
     /* layout */
     layout->stripe_unit = le32_to_cpu(info->layout.fl_stripe_unit);
```

**步骤3：分析漏洞原因**：
- `info->layout.fl_stripe_unit` 来自网络（Ceph 协议）
- 如果 `fl_stripe_unit == 0`，后续计算会除零
- 导致内核崩溃（DoS）或任意代码执行

**步骤4：编写 PoC**：
```c
// 构造恶意的 Ceph 消息
struct ceph_mds_reply_info_in {
    struct ceph_file_layout layout;
};

layout.fl_stripe_unit = 0;  // 触发漏洞
send_ceph_message(layout);
```
