## 5.1 逆向工程概述

### 5.1.1 什么是逆向工程

逆向工程（Reverse Engineering）是指通过对已有产品的分析，推导出其设计原理、实现方法或工作机理的过程。在软件安全领域，逆向工程特指从可执行二进制文件中还原源代码逻辑的技术——将机器码（Machine Code）"逆翻译"为人类可读的汇编代码乃至高级语言表示。

对于漏洞挖掘而言，逆向工程是不可或缺的基础能力。几乎所有的漏洞分析工作都始于对目标二进制文件的反汇编与反编译：

- **未开源的程序**：只能通过逆向分析理解其行为
- **闭源组件/库**：需要逆向定位接口与内部实现
- **固件/嵌入式系统**：通常以二进制形式分发
- **恶意软件**：必须在沙箱中逆向分析行为

### 5.1.2 逆向工程的技术栈

现代逆向工程工具链可以按抽象层级分类：

| 层级 | 工具/技术 | 用途 |
|------|-----------|------|
| **反汇编** | IDA Pro, Ghidra, Radare2, objdump | 机器码 → 汇编 |
| **反编译** | Hex-Rays Decompiler (IDA), Ghidra Decompiler | 汇编 → 类 C 伪代码 |
| **动态分析** | x64dbg, OllyDbg, GDB, WinDbg | 运行时调试分析 |
| **符号执行** | angr, Triton, S2E | 符号化路径分析 |
| **中间表示** | REIL, VEX, BAP, Ghidra PCode | 跨架构统一 IR |

### 5.1.3 逆向分析的工作流程

一个典型的逆向分析流程如下：

```
二进制文件
    ↓
文件格式解析 (PE/ELF/Mach-O)
    ↓
反汇编 (Disassembly)
    ↓
函数识别与边界判定
    ↓
控制流图 (CFG) 重建
    ↓
数据流分析
    ↓
类型恢复与结构体还原
    ↓
反编译 (Decompilation)
    ↓
伪代码 → 人工理解
```

**关键选择**：在漏洞挖掘中，是选择**静态分析**（完全不运行程序）还是**动态分析**（通过调试器观察运行时状态），取决于漏洞的类型和可利用性。静态分析覆盖面广但可能遗漏运行时状态相关的漏洞；动态分析精准但只能覆盖已执行的路径。实战中往往两者结合。

### 5.2.3 核心操作实战详解

#### 5.2.3.1 导航与定位（G 键）

`G` 键是 IDA 中使用频率最高的操作。按下 `G` 后输入地址（十六进制）或符号名称即可跳转。

**实战场景**：你从调试器日志中看到一条错误发生在地址 `0x401234`，在 IDA 中按 `G` → 输入 `401234` → Enter，直接定位到该地址的指令。

**技巧**：
- 支持输入函数名：`G` → `sub_401000` → Enter
- 支持段偏移：`G` → `.rdata:0x100` → Enter（但更常用直接地址）
- 支持表达式：`G` → `main + 0x10` → Enter（需启用 IDAPython 表达式支持）

#### 5.2.3.2 交叉引用（X 键）

交叉引用（Cross Reference，简称 xref）是逆向分析中最强大的功能之一。它告诉你某个地址被哪些其他地址引用。

**实战场景**：你发现一个可疑的全局变量 `g_config`，想知道所有读写该变量位置：

1. 光标放在 `g_config` 上
2. 按 `X` 键
3. 弹出交叉引用窗口，列出所有引用位置
4. 双击任一引用跳转到对应位置

**类型区分**：
- `data` → 数据引用（变量被读写）
- `code` → 代码引用（函数被调用）
- `offset` → 偏移引用
- `cref` → 代码交叉引用

IDA 在交叉引用窗口中用颜色区分引用类型：
- 红色 → 跳转（jmp）
- 绿色 → 调用（call）
- 蓝色 → 数据引用（lea、mov 等）

#### 5.2.3.3 图形视图与文本视图切换（Space）

`Space` 键在图形视图（Graph View）和文本视图（Text View）之间切换。

**图形视图**：以流程图形式展示基本块（Basic Block）和控制流边。每个基本块是一个矩形，不同颜色的箭头表示：
- **绿色箭头** → `jz`/`je`（条件成立时跳转，即 True Branch）
- **红色箭头** → `jnz`/`jne`（条件不成立时的 Fall-through）
- **蓝色箭头** → 无条件跳转

**文本视图**：显示传统线性汇编代码，适合精读和编辑。

**技巧**：在图形视图中按 `Middle Mouse Button（中键）` 拖拽平移；滚动滚轮缩放。

#### 5.2.3.4 重命名（N 键）

`N` 键用于重命名当前地址、函数或变量。这是提升代码可读性的关键操作。

**实战场景**：你在分析一个加密函数，IDA 自动命名为 `sub_401A40`，但你通过字符串分析发现它叫 `AES_Encrypt`：

1. 定位到 `sub_401A40` 的函数名
2. 按 `N` 键
3. 输入 `AES_Encrypt`
4. Enter 确认

此后所有调用该函数的位置也会显示 `AES_Encrypt`，交叉引用窗口同步更新。

**批量重命名策略**：
- 字符串相关函数 → `strlen`、`memcpy`、`strcmp` 等（匹配 CRT 函数）
- 加密相关函数 → `encrypt_block`、`decrypt_packet` 等
- 工具函数 → `parse_header`、`validate_checksum` 等
- 回调函数 → `on_connect`、`on_disconnect` 等

### 5.2.4 反编译窗口（F5 / Tab）

Hex-Rays Decompiler 是 IDA Pro 的核心增值组件，能将汇编代码转化为类 C 的伪代码（Pseudocode）。

**操作流程**：

1. 定位到目标函数（G + 函数名）
2. 按 `F5` 或 `Tab` 打开反编译窗口
3. 阅读伪代码理解逻辑
4. 在伪代码窗口中直接编辑（重命名、改类型）
5. 按 `Tab` 回到汇编视图

**伪代码窗口快捷键**：

| 快捷键 | 功能 |
|--------|------|
| **N** | 重命名变量/函数 |
| **Y** | 修改变量/函数类型 |
| **/** | 在当前行添加注释 |
| **Insert** | 插入新行（添加代码） |
| **Delete** | 删除选中行 |
| **Tab** | 切换到对应的汇编视图 |
| **Esc** | 关闭反编译窗口 |
| **Ctrl+Shift+Enter** | 重新反编译 |
| **F5** | 刷新/重新反编译 |

**伪代码窗口的颜色约定**：
- 蓝色 → 函数名
- 绿色 → 局部变量
- 红色 → 全局变量
- 暗色 → 类型/宏

**实战技巧**：
- 当反编译结果不可读时，尝试使用 `Y` 修正函数签名
- 当局部变量识别错误时，手动定义栈帧布局
- 使用 `Edit → Plugins → Hex-Rays Decompiler → Options` 调整反编译参数

### 5.2.5 Hex View（十六进制视图）

Hex View 显示原始二进制数据，当需要查看指令的机器码编码、修改二进制字节或分析文件结构时使用。

**操作技巧**：
- `D` → 将当前字节切换为数据格式（Byte/Word/Dword/Qword 循环切换）
- `E` → 编辑字节（弹出编辑对话框）
- `G` → 跳转到指定地址的十六进制视图
- `Alt+B` → 二进制搜索
- `Ctrl+F` → 打开搜索面板（Hex View 专属）

**联动技巧**：双击 Disassembly View 中的指令，Hex View 会自动同步到该指令的首字节。反之亦然。

### 5.2.6 Structures 视图（结构体定义）

Structures（`Shift+F9` 或 View → Open Subviews → Structures）用于定义和查看结构体类型。

**手动添加结构体步骤**：

1. 打开 Structures 窗口
2. 按 `Insert` 键新建结构体
3. 输入结构体名称（如 `_MY_HEADER`）
4. 按 `D` 添加成员（Byte/Word/Dword）
5. 按 `N` 重命名成员
6. 使用 `T` 将结构体应用到代码中的地址

**导入标准结构体**：

```
File → Load File → Parse C Header File...
```

选择 Windows SDK 头文件或自定义头文件，IDA 将解析所有结构体和类型定义。

**常见技巧**：在反编译窗口中对某个变量按 `Y`，输入 `MyStruct*`，即可将其标记为结构体指针，伪代码将自动显示成员访问。

### 5.2.7 Enums 视图（枚举定义）

Enums 窗口（`Shift+F10` 或 View → Open Subviews → Enums）用于定义枚举类型，提升反编译代码的可读性。

**添加枚举**：

1. 打开 Enums 窗口
2. Insert → 输入枚举名
3. 为每个成员输入名称和值

**批量导入**：通过 IDAPython 导入：

```python
import idc
idc.add_enum(-1, "ErrorCode", 0)
idc.add_enum_member("ErrorCode", "SUCCESS", 0, 4)
idc.add_enum_member("ErrorCode", "ERR_TIMEOUT", 1, 4)
idc.add_enum_member("ErrorCode", "ERR_ACCESS", 2, 4)
```

枚举在反编译窗口中会自动以名称形式显示，如 `if (ret == ERR_TIMEOUT)`。

### 5.3.2 函数遍历与信息提取

#### 遍历所有函数

```python
import idautils
import idc

for func_ea in idautils.Functions():
    func_name = idc.get_func_name(func_ea)
    func_size = idc.get_func_attr(func_ea, idc.FUNCATTR_END) - func_ea
    print(f"0x{func_ea:X}: {func_name} ({func_size} bytes)")
```

#### 提取函数调用关系

```python
import idautils
import ida_xref

def get_callees(func_ea):
    """获取一个函数调用的所有子函数"""
    callees = set()
    for xref in idautils.XrefsFrom(func_ea, ida_xref.XREF_FAR):
        if xref.type == ida_xref.dr_C:  # Code call
            callees.add(xref.to)
    return callees

def get_callers(func_ea):
    """获取调用一个函数的所有父函数"""
    callers = set()
    for xref in idautils.XrefsTo(func_ea):
        if xref.type == ida_xref.dr_C:  # Code call
            callers.add(xref.frm)
    return callers

# 示例：打印函数调用图
print("Function Call Graph:")
for func_ea in idautils.Functions():
    fname = idc.get_func_name(func_ea)
    callees = get_callees(func_ea)
    if callees:
        callee_names = [idc.get_func_name(c) for c in callees if idc.get_func_name(c)]
        print(f"{fname} calls: {', '.join(callee_names)}")
```

### 5.3.3 交叉引用分析

```python
import idautils
import idc

def analyze_xrefs(addr):
    """分析指定地址的交叉引用"""
    print(f"=== Xrefs to 0x{addr:X} ({idc.get_name(addr)}) ===")
    for xref in idautils.XrefsTo(addr):
        src_func = idaapi.get_func(xref.frm)
        src_func_name = idc.get_func_name(xref.frm) if src_func else "no_func"
        print(f"  From: 0x{xref.frm:X} ({src_func_name})")
        print(f"  Type: {xref.type}")  # dr_C=call, dr_J=jmp, etc.
        print(f"  Distance: {xref.iscode}")
        print()

    print(f"=== Xrefs from 0x{addr:X} ===")
    for xref in idautils.XrefsFrom(addr):
        dst_name = idc.get_name(xref.to) or idc.get_func_name(xref.to) or "?"
        print(f"  To: 0x{xref.to:X} ({dst_name}), type={xref.type}")
```

### 5.3.4 批量重命名函数

```python
import idautils
import idc
import re

def batch_rename_funcs(pattern, replacement, dry_run=True):
    """
    根据模式匹配批量重命名函数
    pattern: 正则表达式
    replacement: 替换字符串（可使用 \\1 等反向引用）
    dry_run: True = 只打印不改写
    """
    renamed = 0
    for func_ea in idautils.Functions():
        old_name = idc.get_func_name(func_ea)
        if re.search(pattern, old_name):
            new_name = re.sub(pattern, replacement, old_name)
            if dry_run:
                print(f"[DRY RUN] 0x{func_ea:X}: {old_name} → {new_name}")
            else:
                if idc.set_name(func_ea, new_name, idc.SN_CHECK):
                    print(f"[RENAMED] 0x{func_ea:X}: {old_name} → {new_name}")
                    renamed += 1
                else:
                    print(f"[FAILED] 0x{func_ea:X}: {old_name} → {new_name}")
    if not dry_run:
        print(f"\nRenamed {renamed} functions")
    return renamed

# 示例：将所有 sub_XXXX 开头的函数统一加前缀
# batch_rename_funcs(r'^(sub_[0-9A-F]+)$', r'unk_\1', dry_run=True)
```

#### 智能命名策略示例

```python
import idautils
import idc

def smart_rename_based_on_strings():
    """
    根据函数引用的字符串内容自动命名函数。
    例如：如果一个函数中包含了 "Login failed" 字符串，自动命名为 login_handler
    """
    for func_ea in idautils.Functions():
        func_name = idc.get_func_name(func_ea)
        if func_name.startswith("sub_"):
            # 获取函数中使用的字符串
            strings_in_func = []
            for head in idautils.FuncItems(func_ea):
                # 检查指令是否引用了字符串
                for xref in idautils.XrefsFrom(head):
                    if idc.get_str_type(xref.to):
                        s = idc.get_strlit_contents(xref.to)
                        if s:
                            strings_in_func.append(s.decode('utf-8', errors='ignore'))
            if strings_in_func:
                # 选择最有代表性的字符串
                best_str = min(strings_in_func, key=lambda s: len(s))
                # 清理字符串并转为合法标识符
                clean_name = ''.join(c if c.isalnum() or c == '_' else '_' for c in best_str)
                clean_name = 'str_' + clean_name[:24]
                try:
                    idc.set_name(func_ea, clean_name, idc.SN_CHECK)
                    print(f"Named 0x{func_ea:X} → {clean_name}")
                except:
                    pass
```

### 5.3.6 自动化分析管道

将上述功能组合，可以构建一个自动化分析脚本管道：

```python
"""
auto_analyze.py - 自动化逆向分析管道
用法：Alt+F7 加载此脚本
"""
import idautils
import idc
import idaapi
import ida_bytes
import ida_funcs
import ida_segment
import json

class AutoAnalyzer:
    def __init__(self, output_path="analysis_report.json"):
        self.output_path = output_path
        self.report = {
            "file_info": {},
            "functions": [],
            "strings": [],
            "imports": [],
            "interesting_patterns": []
        }

    def collect_file_info(self):
        """收集文件基本信息"""
        self.report["file_info"] = {
            "input_file": idc.get_input_file_path(),
            "base_address": hex(idaapi.get_imagebase()),
            "processor": idaapi.getinfostructure().procName,
            "bitness": "32-bit" if idaapi.getinfostructure().is_32bit() else "64-bit" if idaapi.getinfostructure().is_64bit() else "16-bit"
        }

    def collect_functions(self):
        """收集所有函数信息"""
        for func_ea in idautils.Functions():
            func = idaapi.get_func(func_ea)
            func_name = idc.get_func_name(func_ea)
            func_size = func.end_ea - func.start_ea

            # 收集基本块信息
            bb_count = 0
            for _ in idautils.Chunks(func_ea):
                bb_count += 1

            # 收集调用关系
            callees = []
            for xref in idautils.XrefsFrom(func_ea):
                if xref.type == ida_xref.dr_C:
                    callee_name = idc.get_func_name(xref.to) or hex(xref.to)
                    callees.append(callee_name)

            self.report["functions"].append({
                "name": func_name,
                "address": hex(func_ea),
                "size": func_size,
                "basic_blocks": bb_count,
                "callees": callees
            })

    def find_interesting_patterns(self):
        """查找潜在的漏洞模式"""
        # 查找 strcpy / gets 等危险函数调用
        dangerous_funcs = ["strcpy", "strcat", "sprintf", "gets", "scanf", "memcpy"]

        for func_ea in idautils.Functions():
            func_name = idc.get_func_name(func_ea)
            if any(d in func_name.lower() for d in dangerous_funcs):
                # 查找所有调用者
                for xref in idautils.XrefsTo(func_ea):
                    caller_func = idaapi.get_func(xref.frm)
                    if caller_func:
                        self.report["interesting_patterns"].append({
                            "type": "dangerous_function_usage",
                            "function": func_name,
                            "caller": idc.get_func_name(caller_func.start_ea),
                            "call_address": hex(xref.frm)
                        })

    def run(self):
        """执行完整分析"""
        print("[*] AutoAnalyzer: Starting analysis...")
        self.collect_file_info()
        print(f"[*] File: {self.report['file_info']['input_file']}")

        print("[*] Collecting functions...")
        self.collect_functions()
        print(f"[*] Found {len(self.report['functions'])} functions")

        print("[*] Finding patterns...")
        self.find_interesting_patterns()
        print(f"[*] Found {len(self.report['interesting_patterns'])} interesting patterns")

        # 输出报告
        with open(self.output_path, 'w', encoding='utf-8') as f:
            json.dump(self.report, f, indent=2, ensure_ascii=False)
        print(f"[*] Report saved to {self.output_path}")

# 执行
analyzer = AutoAnalyzer()
analyzer.run()
```

```python
            f.write(func_code)
            f.write("\n\n/*****************************/\n\n")

    print(f"Exported decompiled code to {output_file}")
```

```python

def find_xrefs_to_address(addr):
    """查找指向指定地址的所有交叉引用"""
    xrefs = currentProgram.getReferenceManager().getReferencesTo(addr)
    results = []
    for xref in xrefs:
        ref_type = xref.getReferenceType()
        from_addr = xref.getFromAddress()
        results.append({
            "from": from_addr,
            "ref_type": str(ref_type),
            "is_call": ref_type.isCall(),
            "is_jump": ref_type.isJump(),
            "is_data": ref_type.isData()
        })
    return results

def find_all_callers(func_name):
    """查找调用指定函数的所有函数"""
    sym_table = currentProgram.getSymbolTable()
    symbols = sym_table.getSymbols(func_name, None)

    if not symbols:
        print(f"Symbol '{func_name}' not found")
        return []

    for sym in symbols:
        print(f"\n=== Callers of {func_name} @ {sym.getAddress()} ===")
        refs = find_xrefs_to_address(sym.getAddress())
        for ref in refs:
            caller_func = get_function_at(ref["from"])
            caller_name = caller_func.getName() if caller_func else "???"
            ref_str = "CALL" if ref["is_call"] else "JMP" if ref["is_jump"] else "DATA"
            print(f"  [{ref_str}] {caller_name} @ {ref['from']}")

def get_function_at(addr):
    """获取指定地址所在的函数"""
    func_mgr = currentProgram.getFunctionManager()
    func = func_mgr.getFunctionContaining(addr)
    return func
```

## 5.7 编译器优化识别

理解编译器优化是逆向分析的关键技能。优化后的二进制代码与源代码有显著差异，但优化的模式是可预测的。

### 5.7.1 常见优化类型

#### (1) 函数内联（Function Inlining）

编译器将小函数的函数体直接插入调用点，避免函数调用开销。

**源代码**：
```c
// test.c - 编译: gcc -O2 test.c
static int add(int a, int b) {
    return a + b;
}

int calc(int x, int y, int z) {
    return add(x, y) + z;
}
```

**无优化（-O0）**：
```asm
calc:
    push    ebp
    mov     ebp, esp
    sub     esp, 4
    mov     eax, [ebp+12]           ; y
    push    eax
    mov     eax, [ebp+8]            ; x
    push    eax
    call    add                     ; 有调用
    add     esp, 8
    add     eax, [ebp+16]           ; + z
    leave
    ret

add:
    push    ebp
    mov     ebp, esp
    mov     eax, [ebp+12]
    mov     edx, [ebp+8]
    add     eax, edx                ; return a + b
    pop     ebp
    ret
```

**有优化（-O2）**：
```asm
calc:
    mov     eax, [esp+4]            ; x
    add     eax, [esp+8]            ; x + y (内联)
    add     eax, [esp+12]           ; (x+y) + z
    ret                             ; 无 call add，简单直接
```

**逆向识别特征**：
- 没有 `call` 指令但实现了子函数的功能
- 函数体逻辑出现在调用者的上下文中
- 编译器会生成 `.cold` 节用于罕见路径的内联展开

#### (2) 循环展开（Loop Unrolling）

将循环体复制多次以减少循环控制和分支开销。

**源代码**：
```c
// 原始循环
int sum = 0;
for (int i = 0; i < 4; i++) {
    sum += arr[i];
}
```

**未展开**：
```asm
    xor     eax, eax          ; sum = 0
    xor     ecx, ecx          ; i = 0
loop_start:
    add     eax, [arr + ecx*4]
    inc     ecx
    cmp     ecx, 4
    jl      loop_start
```

**展开为4次**：
```asm
    mov     eax, [arr]        ; arr[0]
    add     eax, [arr+4]      ; arr[1]
    add     eax, [arr+8]      ; arr[2]
    add     eax, [arr+12]     ; arr[3]
    ; 无循环指令！
```

**逆向识别特征**：
- 循环计数器消失，只有重复的线性指令序列
- 重复的指令序列且地址偏移呈等差数列
- 当展开不完整时，会看到循环 + 部分展开的组合

#### (3) 死代码消除（Dead Code Elimination, DCE）

编译器删除计算结果未被使用的代码和不可达代码。

**源代码**：
```c
int process(int x, int y) {
    int tmp = x * 2;        // 如果 tmp 后续未被使用，此句会被删除
    int result = x + y;
    printf("%d", result);
    return 0;
    // return result;        // 如果函数最后 return 0 而不是 result，
}                            // return 之前的 result 计算仍然保留，因为 printf 用了
```

**优化后可能变为**：
```asm
process:
    push    {result}
    mov     eax, [esp+8]    ; x
    add     eax, [esp+12]   ; x + y
    push    eax
    push    str_%d
    call    printf
    add     esp, 8
    xor     eax, eax        ; return 0
    ret
```

**逆向识别特征**：
- 某些变量在伪代码中不存在
- 函数的某些参数计算被省略
- 条件分支看似被简化

#### (4) 寄存器分配（Register Allocation）

编译器将频繁使用的变量存放在寄存器中而非内存栈中。

**未优化**（频繁栈操作）：
```asm
    mov     dword [ebp-4], 0       ; int i = 0
    mov     dword [ebp-8], 10      ; int n = 10
loop:
    mov     eax, [ebp-4]
    add     eax, 1
    mov     [ebp-4], eax           ; i++ (写回内存)
    mov     eax, [ebp-4]
    cmp     eax, [ebp-8]
    jl      loop
```

**优化后**（寄存器分配）：
```asm
    xor     eax, eax               ; int i = 0 (在 EAX 中)
    mov     ecx, 10                ; int n = 10 (在 ECX 中)
loop:
    inc     eax                    ; i++ (寄存器操作)
    cmp     eax, ecx
    jl      loop
```

#### (5) 常量折叠与传播（Constant Folding & Propagation）

```c
// 源代码
int x = 5;
int y = x * 3 + 2;
return y;

// 编译优化后直接为
return 17;
```

#### (6) 公共子表达式消除（CSE）

```c
// 源代码
int a = x * y + 1;
int b = x * y + 2;

// 优化后
int tmp = x * y;
int a = tmp + 1;
int b = tmp + 2;
```

#### (7) 尾调用优化（Tail Call Optimization）

当函数最后一句调用另一个函数并立即返回其结果时，编译器将 `call` 替换为 `jmp` 以复用栈帧：

```asm
; 未优化
function_a:
    ...
    call    function_b
    ret

; 尾调用优化后
function_a:
    ...
    jmp     function_b    ; 无 call/ret，复用栈帧
    ; 无 ret 指令！
```

### 5.7.2 编译优化级别速查

| GCC 标志 | 效果 | 逆向难度 |
|----------|------|----------|
| `-O0` | 无优化，代码直译 | 低 |
| `-O1` | 基础优化（局部优化） | 中 |
| `-O2` | 标准优化（大部分优化开启） | 高 |
| `-O3` | 激进优化（含向量化、函数内联） | 极高 |
| `-Os` | 体积优化（代码最小化） | 中高 |
| `-Ofast` | -O3 + 浮点精度放宽 | 极高 |

### 5.7.3 编译器特征识别

不同编译器生成的代码具有不同特征，识别编译器有助于更精准地还原逻辑：

**GCC 特征**：
- 栈对齐通常为 16 字节
- 使用 `__stack_chk_fail` 进行栈保护
- 函数前缀有 `.cfi_*` 伪指令（DWARF）
- GOT/PLT 跳转表结构
- C++ 异常使用 `_Unwind_*` 机制

**MSVC 特征**：
- `_security_cookie`（GS 保护）
- `_except_handler4_common`（SEH 异常）
- `__stdcall` / `__thiscall` / `__fastcall` 调用约定
- C++ 使用 `_CallMemberFunction0` 等 thunk
- `mov edi, edi` / `int 3` 开头（Hot Patch header）

**Clang/LLVM 特征**：
- 使用 `asan.module_ctor`（ASAN 开启时）
- OLLVM 混淆时看到大量不透明谓词
- LTO（链接时优化）导致函数边界模糊

## 5.8 控制流图重建

控制流图（Control Flow Graph, CFG）是程序分析的基础数据结构，每个基本块（Basic Block）是一个节点，控制流转移是边。

### 5.8.1 基本块识别

**基本块的结束条件**：

1. **无条件跳转**：`jmp`、`jmp [eax*4+table]`
2. **条件跳转**：`jz`、`jnz`、`jg`、`jl` 等
3. **函数调用**：`call`（通常结束块，但视上下文而定）
4. **函数返回**：`ret`、`retn`、`iret`
5. **异常指令**：`int 3`、`ud2`
6. **分支目标**：跳转的目标地址开始新的基本块

### 5.8.2 if/else 结构识别

```c
if (condition) {
    // then-block
} else {
    // else-block
}
```

**典型汇编模式**：

```asm
    ; 条件检查
    cmp     eax, 5          ; 比较
    jle     else_block      ; 如果 <=5 跳 else

    ; then-block 开始
    mov     ecx, 1
    call    do_something
    jmp     end_if           ; 跳过 else 块

    ; else-block 开始
else_block:
    xor     ecx, ecx
    call    do_other

    ; if/else 结束
end_if:
```

**基本块图**：

```
         [cmp eax, 5]
              │
        ┌─────┴─────┐
        │            │
    [jle]          [fallthrough]
        │            │
        ▼            ▼
   [else_block]  [then_block]
        │            │
        └─────┬─────┘
              │
              ▼
          [end_if]
```

### 5.8.3 switch/case 识别

switch 有两种典型实现方式：

#### 跳转表（Jump Table，case 连续时）

```asm
    mov     eax, [var]      ; switch variable
    cmp     eax, 3          ; max case value check
    ja      default_case    ; > 3 → default
    jmp     [jump_table + eax*4]  ; 跳转表索引

jump_table:
    dd case0_addr    ; index 0
    dd case1_addr    ; index 1
    dd case2_addr    ; index 2
    dd case3_addr    ; index 3
```

#### 分支树（if-else chain，case 稀疏时）


### 5.8.5 调用图重建

调用图（Call Graph）展示函数之间的调用关系，是理解程序结构和攻击面的关键。

**使用 IDAPython 导出调用图**：

```python
import json

def build_call_graph(output_file="callgraph.json"):
    """构建完整的函数调用图"""
    graph = {
        "nodes": [],
        "edges": [],
        "metadata": {}
    }

    # 收集所有函数节点
    func_ids = {}
    for idx, func_ea in enumerate(idautils.Functions()):
        func_name = idc.get_func_name(func_ea)
        func = idaapi.get_func(func_ea)
        if not func:
            continue

        node_id = f"func_{idx}"
        func_ids[func_ea] = node_id
        graph["nodes"].append({
            "id": node_id,
            "name": func_name,
            "address": func_ea,
            "size": func.size(),
            "type": "thunk" if (func.flags & ida_funcs.FUNC_THUNK) else "normal"
        })

    # 收集调用边
    for idx, func_ea in enumerate(idautils.Functions()):
        caller_id = func_ids.get(func_ea)
        if not caller_id:
            continue

        for xref in idautils.XrefsFrom(func_ea, ida_xref.XREF_FAR):
            if xref.type == ida_xref.dr_C:
                callee_id = func_ids.get(xref.to)
                if callee_id:
                    graph["edges"].append({
                        "source": caller_id,
                        "target": callee_id,
                        "type": "call"
                    })

    # 使用 Graphviz 格式输出
    dot = ["digraph CallGraph {"]
    dot.append('  rankdir="LR";')
    dot.append('  node [shape=box, style="rounded"];')
    for node in graph["nodes"]:
        label = f"{node['name']}\\n0x{node['address']:X}"
        dot.append(f'  {node["id"]} [label="{label}"];')
    for edge in graph["edges"]:
        dot.append(f'  {edge["source"]} -> {edge["target"]};')
    dot.append("}")

    # 保存 Graphviz DOT 文件
    with open(output_file.replace('.json', '.dot'), 'w') as f:
        f.write('\n'.join(dot))

    print(f"Call graph saved: {output_file.replace('.json', '.dot')}")
    print(f"  Nodes: {len(graph['nodes'])}, Edges: {len(graph['edges'])}")

```

## 5.9 函数参数与调用约定

### 5.9.1 调用约定概览

调用约定（Calling Convention）定义了函数如何接收参数和返回值。不同架构和操作系统有不同的约定。

#### x86 (32-bit) 调用约定

| 约定 | 参数传递 | 栈清理 | 函数名修饰 |
|------|----------|--------|------------|
| **cdecl** | 栈（从右到左压栈） | 调用者 | `_function` |
| **stdcall** | 栈（从右到左压栈） | 被调用者 | `_function@N` |
| **fastcall** | ECX/EDX + 栈 | 被调用者 | `@function@N` |
| **thiscall** | ECX(this) + 栈 | 被调用者（MSVC） | `_function@N` |

`N` 表示参数栈空间的总字节数（每个 DWORD 4 字节）。

**示例：cdecl 调用**（参数从右向左压栈）：
```asm
    push    arg3            ; 最后一个参数先压栈
    push    arg2
    push    arg1            ; 第一个参数最后压栈
    call    function
    add     esp, 12         ; 调用者清理 12 字节（3 个参数）
```

**示例：stdcall 调用**：
```asm
    push    arg3
    push    arg2
    push    arg1
    call    function        ; function 内部以 ret 12 返回，自动清理
    ; 无 add esp, N，因为被调用者已清理
```

#### x64 (64-bit) 调用约定

##### Windows x64

| 参数位置 | 寄存器 | 说明 |
|----------|--------|------|
| 1st | RCX | 整数/指针 |
| 2nd | RDX | 整数/指针 |
| 3rd | R8 | 整数/指针 |
| 4th | R9 | 整数/指针 |
| 5th+ | [RSP+阴影空间] | 栈传递 |
| 返回值 | RAX | 返回值 |

**阴影空间（Shadow Space / Home Space）**：调用者必须在栈上预留 32 字节（4 个 8 字节槽），即使前 4 个参数通过寄存器传递。这是 Windows x64 的强制要求。

**示例**（`func(a, b, c, d, e)` 5 参数）：
```asm
    sub     rsp, 48         ; 预留阴影空间(32) + 第5参数(8) + 对齐
    mov     r9, d            ; 第4个参数
    mov     r8, c            ; 第3个参数
    mov     rdx, b           ; 第2个参数
    mov     rcx, a           ; 第1个参数
    mov     [rsp+32], e     ; 第5个参数在栈上
    call    func
    add     rsp, 48
```

##### System V (Linux/Mac x64)

| 参数位置 | 寄存器 |
|----------|--------|
| 1st | RDI |
| 2nd | RSI |
| 3rd | RDX |
| 4th | RCX |
| 5th | R8 |
| 6th | R9 |
| 7th+ | 栈（从右到左） |
| 返回值 | RAX |

**差异点**：Linux x64 使用 6 个寄存器参数传递，不需要阴影空间。更少的参数通过栈传递。

### 5.9.2 局部变量识别

局部变量存储在栈上，通过 `EBP`/`RBP` 或 `ESP`/`RSP` 间接寻址：

#### 帧指针模式（有 EBP/RBP）

```asm
; 函数序言
push    ebp
mov     ebp, esp
sub     esp, 16            ; 分配 16 字节局部变量空间

; 访问局部变量
mov     dword [ebp-4], 0   ; int local_a (ebp-4)
mov     dword [ebp-8], 10  ; int local_b (ebp-8)
mov     dword [ebp-12], 20 ; int local_c (ebp-12)
mov     [ebp-16], eax      ; char* local_d (ebp-16)

; 访问参数
mov     eax, [ebp+8]       ; 第一个参数 (arg1)
mov     eax, [ebp+12]      ; 第二个参数 (arg2)
; ...

; 函数结语
leave                     ; mov esp, ebp; pop ebp
ret N                     ; 返回
```

**变量布局**（x86 cdecl 架构）：

```
High Address
    +----------------+
    | arg3           |  ebp + 12
    | arg2           |  ebp + 8
    | return address |  ebp + 4
    | saved EBP      |  ebp + 0  ← EBP
    | local1         |  ebp - 4
    | local2         |  ebp - 8
    | local3         |  ebp - 12
    | ...            |
    +----------------+  ← ESP
Low Address
```

#### 无帧指针模式（FPO, Frame Pointer Omission）

`-O1` 以上优化级别会省略 EBP（通过 `-fomit-frame-pointer` 控制），改用 ESP/RSP 访问局部变量：

```asm
sub     esp, 16
mov     dword [esp+12], 0    ; local_a
mov     dword [esp+8], 10    ; local_b
mov     dword [esp+4], 20    ; local_c

; 参数访问需知道调用前的栈布局
; 访问 arg1: [esp + 16 + 4] + 偏移
```

**逆向难点**：FPO 使函数边界模糊，参数偏移关系不直观。IDA 的栈帧分析功能可帮助恢复。

### 5.9.3 从反汇编还原函数签名

#### 手动还原的例子

假设反汇编如下：

```asm
0x401000: push    ebp
0x401001: mov     ebp, esp
0x401003: sub     esp, 16
0x401006: mov     dword [ebp+8], 0
0x40100D: mov     eax, [ebp+12]
0x401010: mov     ecx, [ebp+16]
0x401013: cmp     eax, ecx
...
0x401030: leave
0x401031: ret
```

**分析过程**：

1. 函数使用 EBP 帧指针，说明不是 FPO
2. `sub esp, 16` → 16 字节的局部变量空间
3. `[ebp+8]` = 参数1 → `arg_0`（通常写入 0，可能是输出参数或局部初始化异常）
4. `[ebp+12]` = 参数2 → `arg_1`（int/char*/DWORD 类型）
5. `[ebp+16]` = 参数3 → `arg_2`（与 arg_1 比较，同类型）
6. 函数中使用 `ret` 而非 `ret N` → cdecl 调用者清理

**还原签名**：

```c
// 参数个数：3
// 类型推断：arg_1 和 arg_2 做比较，可能是整数或指针
int __cdecl some_func(int arg_0, int arg_1, int arg_2)
```

#### 64 位参数还原

```asm
0x140001000: sub     rsp, 40          ; 分配栈空间(阴影+对齐)
0x140001004: mov     dword [rsp+32], 0 ; local var
0x14000100C: mov     rax, rcx          ; arg1 (RCX)
0x14000100F: mov     rdx, rax          ; arg2 (RDX)
0x140001012: call    process_data
...
0x140001030: add     rsp, 40
0x140001034: ret
```

**分析过程**：

1. `sub rsp, 40` → 40 字节栈空间（32 阴影 + 8 局部）
2. `rcx` → 参数1 → 函数至少接受一个参数
3. 将 RCX 传给 RDX → 可能是 `func(arg1, arg1)`
4. 没有修改 RDX → 第二个参数就是第一个参数的值
5. `ret` → 不需要栈清理（Windows x64 调用者总是清理阴影空间）

**还原签名**：
```c
// Windows x64 调用约定
void func(void* arg1, void* arg2);
```

```python
import idc
import idautils

def analyze_function_types(func_ea):
    """分析函数的参数和局部变量"""
    func = idaapi.get_func(func_ea)
    if not func:
        print("Invalid function address")
        return

    func_name = idc.get_func_name(func_ea)

    print(f"Frame base: {func.frreg}")  # Frame register (EBP/RBP)

    # 获取栈帧大小
    frame = idaapi.get_frame(func_ea)
    if frame:
        frame_size = frame.get_frame_size()
        lvars = frame.get_lvar_size()
        args = frame.get_arg_size()
        print(f"Frame size: {frame_size}")
        print(f"Local variables: {lvars} bytes")
        print(f"Arguments: {args} bytes")

        # 枚举栈成员
        print(f"\nStack layout:")
        for i in range(frame.get_member_qty()):
            member = frame.get_member_by_id(i)
            if member:
                offset = member.get_soff()
                mtype = member.get_type_name() or "?"
                mname = member.get_name()
                msize = member.get_size()
                region = "ARG" if offset > 0 else "LOCAL"
                print(f"  [{region}] {mname} @ ebp{'%+d' % offset} ({mtype}, {msize} bytes)")

    # 显示函数类型签名
    ty = idc.get_type(func_ea)
    if ty:
        print(f"\nCurrent type: {ty}")
```

## 5.11 Obfuscation 初步

代码混淆（Code Obfuscation）是逆向工程的高级对抗技术。掌握基本混淆识别是漏洞挖掘的进阶技能。

### 5.11.1 OLLVM (Obfuscator-LLVM)

OLLVM 是基于 LLVM 的控制流平坦化混淆工具，在 CTF 和恶意软件中广泛使用。

#### 控制流平坦化（Control Flow Flattening）

**原始代码**：
```c
int check_license(const char* key) {
    if (strlen(key) != 16) return 0;
    if (key[0] != 'A') return 0;
    if (key[4] != '-') return 0;
    if (CRC32(key) == 0xDEADBEEF) return 1;
    return 0;
}
```

**OLLVM 混淆后**（控制流平坦化）：
```c
int check_license(const char* key) {
    int state = 0;
    while (1) {
        switch (state) {
            case 0:  state = 1; break;
            case 1:  if (strlen(key) != 16) { state = 999; } else { state = 2; } break;
            case 2:  if (key[0] != 'A') { state = 999; } else { state = 3; } break;
            case 3:  if (key[4] != '-') { state = 999; } else { state = 4; } break;
            case 4:  if (CRC32(key) == 0xDEADBEEF) { state = 5; } else { state = 999; } break;
            case 5:  return 1;
            case 999: return 0;
            default: state = 999; break;
        }
    }
}
```

**混淆后的汇编特征**：
- 函数体只有一个巨大的循环（while/for）
- 循环内有一个 switch 或分支链
- 所有原始逻辑被编码为 state 变量的值
- 原始的控制流关系被破坏

**对抗方法**：
1. **符号执行**（angr、Triton）：自动分析所有路径
2. **模式匹配**：识别 state 变量，重构控制流
3. **动态跟踪**：记录 state 变化轨迹

#### 不透明谓词（Opaque Predicate）

引入一个运行时可确定但静态分析很难判断的条件：

```c
// 一个恒真但难以分析的谓词
int opaque_predicate() {
    int x = random();
    int y = random();
    return (x * (x + 1)) % 2 == 0;  // 总是为真
}

// 在代码中插入死代码
if (opaque_predicate()) {
    real_code();        // 总是执行
} else {
    dead_code();        // 永远不会执行，但迷惑逆向者
}
```

**汇编识别特征**：
- 复杂的算术运算结果用于条件判断
- 使用不相干的全局变量
- 条件分支的基本块是死代码（永远不会被执行到）
- 反编译器中观察到可疑的 `if (xxx)`，但跳转方向固定

### 5.11.2 花指令（Junk Code / Junk Instructions）

花指令是在正常指令流中插入的无用指令字节，破坏线性扫描反汇编的正确性。

**示例**：

```asm
; 原始代码
    mov     eax, [esp+4]
    call    authenticate

; 插入花指令后
    mov     eax, [esp+4]
    push    eax
    pop     eax                    ; push/pop 对，无实际效果
    push    ecx
    ; 插入看似重要的比较
    cmp     eax, 0x12345678
    jnz     real_target_1
fake_target:                       ; 花指令块，实际不可能到达
    db      0xE8                   ; call opcode 的一部分
    db      0xFF, 0xFF             ; 垃圾数据
real_target_1:
    call    authenticate
```

**花指令对抗策略（IDAPython 去花）**：

```python
import ida_bytes
import idc

def is_junk_push_pop(ea):
    """检查是否是 push/pop 花指令模式"""
    inst = idaapi.get_instruction(ea)
    if not inst:
        return False

    mnem = inst.mnemonic.lower()
    size = inst.size

    if mnem == "push":
        # 检查下一条指令是否对应 pop
        next_ea = ea + size
        next_inst = idaapi.get_instruction(next_ea)
        if next_inst and next_inst.mnemonic.lower() == "pop":
            return True
    return False

def remove_junk_code(from_ea, to_ea):
    """删除指定范围内的花指令"""
    ea = from_ea
    nop_count = 0
    junk_count = 0

    while ea < to_ea:
        if is_junk_push_pop(ea):
            # 两个指令（push+pop）共 2 字节（32位，push eax=50, pop eax=58）
            junk_size = 2
            for i in range(junk_size):
                ida_bytes.patch_byte(ea + i, 0x90)  # NOP
            junk_count += 1
            ea += junk_size
        elif is_trap_instruction(ea):
            # 检测陷阱指令并 NOP
            inst = idaapi.get_instruction(ea)
            if inst:
                for i in range(inst.size):
                    ida_bytes.patch_byte(ea + i, 0x90)
                junk_count += 1
                ea += inst.size
        else:
            ea += idaapi.get_instruction(ea).size if idaapi.get_instruction(ea) else 1

    print(f"Removed {junk_count} junk patterns, NOPped {nop_count} bytes")
```

### 5.11.3 反调试技术

常见的反调试手段及其汇编特征：

#### (1) `IsDebuggerPresent` (Windows)

```asm
; 通过 PEB 的 BeingDebugged 标志
mov     eax, fs:[30h]      ; PEB 地址
movzx   eax, byte [eax+2]  ; BeingDebugged 标志
test    eax, eax
jnz     being_debugged      ; 如果被调试则跳转
```

#### (2) `NtGlobalFlag`

```asm
mov     eax, fs:[30h]
mov     eax, [eax+68h]     ; NtGlobalFlag
test    eax, 0x70           ; FLG_HEAP_ENABLE_TAIL_CHECK | FLG_HEAP_ENABLE_FREE_CHECK | FLG_HEAP_VALIDATE_PARAMETERS
jnz     being_debugged
```

#### (3) INT 3 断点检测

```asm
; 检查代码是否被 INT 3 打补丁
mov     eax, dword [some_function]
cmp     eax, 0xCCCCCCCC    ; INT 3 通常是 0xCC
je      breakpoint_found
```

#### (4) 时间差检测

```asm
rdtsc                      ; 读取时间戳计数器
mov     [start], eax
; ... 执行代码 ...
rdtsc
sub     eax, [start]
cmp     eax, threshold     ; 如果执行时间过长 → 被调试
jg      being_debugged
```

### 5.11.4 字符串加密

```asm
; 加密字符串在运行时解密
encoded_str:
    db 0x8B, 0xC3, 0x5F, 0x92, ... ; XOR 加密

decrypt_loop:
    xor     byte [ecx], 0x55        ; 使用 XOR 0x55 解密
    inc     ecx
    cmp     ecx, end_addr
    jl      decrypt_loop
```

**逆向对抗**：
- 硬件断点在解密后的字符串访问处
- 使用字符串搜索插件（IDA FindCrypt 等）
- 手动解密：`解密后字符串 = 加密字节 XOR 密钥`
