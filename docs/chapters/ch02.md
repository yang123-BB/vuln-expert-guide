# 第 2 章：搭建漏洞研究环境

> **难度**：⭐⭐  
> **预计时间**：90 分钟

---

## 2.1 本章概述

漏洞研究是一项高度依赖工具链的工程实践。与普通的软件开发不同，逆向工程、模糊测试（Fuzzing）、动态调试等操作对操作系统、CPU 架构、编译器版本乃至内核特性均有严格要求。如果在一台混用各类软件的主机上进行研究，常常会遇到工具之间的依赖冲突、版本不兼容等问题，轻则浪费大量时间排查，重则导致分析结果错误。

本章的目标是为读者构建一套**稳定、可复现、高兼容性**的漏洞研究环境。我们将在一台主流 x86_64 物理机上，通过虚拟机安装专用的 Ubuntu 22.04 LTS 系统，然后在其中依次安装和配置以下核心工具：

| 工具 | 用途 | 优先级 |
|------|------|--------|
| VMware Workstation / VirtualBox | 虚拟化平台 | ⭐⭐⭐ |
| Ubuntu 22.04 LTS | 基础操作系统 | ⭐⭐⭐ |
| IDA Pro (Free/Commercial) | 静态逆向分析 | ⭐⭐⭐ |
| Ghidra | 开源逆向框架 | ⭐⭐⭐ |
| AFL++ | 覆盖率引导模糊测试 | ⭐⭐⭐ |
| GDB + pwndbg | 动态调试 | ⭐⭐⭐ |
| QEMU (User-mode) | 跨架构模拟 | ⭐⭐ |

完成本章所有步骤后，你将拥有一个功能完整的研究环境，可无缝衔接后续各章节的漏洞挖掘实验。

## 2.2 安装虚拟机平台

### 2.2.1 VMware Workstation Pro

VMware Workstation 是 VMware 公司推出的桌面虚拟化软件，在二进制安全领域拥有最广泛的用户基础。其内核稳定、对 USB 设备/快照/克隆等特性支持完善，且在调试时对嵌套虚拟化（如在 VM 中运行容器）的支持优于竞品。

#### 2.2.1.1 下载与安装

**下载地址**：`https://www.vmware.com/products/workstation-pro/workstation-pro-evaluation.html`

VMware Workstation Pro 17 可免费试用 30 天，但试用期结束后需要购买许可证。对于学习用途，亦可长期使用 VMware Workstation 16 旧版本（免费，无需许可证，功能足够）。

**安装步骤（Windows 宿主机）**：

1. 关闭宿主机的 Hyper-V（若同时安装了 Docker Desktop，可能存在冲突）。可在 PowerShell 中执行：

```powershell
# 关闭 Hyper-V（需重启）
bcdedit /set hypervisorlaunchtype off
```

2. 下载 `VMware-workstation-full-17.x.x.exe`，双击运行安装程序。
3. 安装路径建议保持默认 `C:\Program Files (x86)\VMware\VMware Workstation\`。
4. 安装过程中勾选 **增强型键盘驱动程序**（可更好地处理特殊按键）。
5. 完成安装后，从桌面快捷方式或开始菜单启动 VMware Workstation。

#### 2.2.1.2 常见问题

**问题 1：安装时提示 "VMware Workstation and Hyper-V are not compatible"**

这是因为宿主机开启了 Hyper-V。解决方案有两个：

- **方案 A**：关闭 Hyper-V（见上），重启后即可安装。
- **方案 B**：保留 Hyper-V，使用 VMware 17 及以上版本，其支持"Windows Hypervisor Platform"模式（Settings → Memory → 勾选 "Virtualize Intel VT-x/EPT or AMD-V/RVI"）。

**问题 2：启动虚拟机时提示 "Not enough physical memory"**

确保宿主机至少保留 8 GB RAM，其中分配给虚拟机的内存不超过宿主机总内存的 50%。在 VMware 虚拟机的 Settings → Memory 中调整。

**问题 3：64-bit 虚拟机选项不可用**

这表明 CPU 未开启虚拟化（VT-x / AMD-V）。解决步骤：

1. 重启电脑，进入 BIOS/UEFI 设置。
2. 找到 **Intel VT-x** 或 **AMD-V** 选项，将其设为 **Enabled**。
3. 保存并退出 BIOS，虚拟机选项将变为可用。

### 2.2.2 VirtualBox（免费替代方案）

如果不愿购买 VMware 许可证，VirtualBox 是功能等效的免费替代品。

**下载地址**：`https://www.virtualbox.org/wiki/Downloads`

选择 **Windows hosts** 版本下载。安装过程为标准"下一步"流程，无需特殊配置。

> **建议**：VMware 在性能和稳定性上略优于 VirtualBox。如果仅用于学习，推荐使用 VMware Workstation 16（免费），其对 4 核以上 CPU 的调度更为高效。

## 2.3 安装 Ubuntu 22.04 LTS 虚拟机

### 2.3.1 为什么选择 Ubuntu 22.04

漏洞研究工具链在 Ubuntu 系列发行版上的兼容性最佳。Ubuntu 22.04 LTS（Long Term Support，维护至 2027 年）具有以下优势：

- **软件包仓库稳定**：主流安全工具（binutils, gdb, python3-dev 等）可直接通过 `apt` 安装，无需从源码编译。
- **GCC 版本适中**：默认 GCC 12，兼容大多数二进制分析工具的编译需求。
- **Python 3.10**：支持几乎所有现代 Python 安全工具（angr, pwntools, angr 等）。
- **LTS 维护周期长**：实验环境搭建一次，可稳定使用数年。

### 2.3.2 创建虚拟机

#### VMware 创建步骤

1. 打开 VMware Workstation，点击 **Create a New Virtual Machine**（创建新虚拟机）。
2. 选择 **Typical (recommended)**，点击 **Next**。
3. 选择 **Installer disc image file (iso)**，点击 **Browse** 导航至已下载的 Ubuntu 22.04 LTS 镜像文件（约 3.5 GB，官网地址：`https://releases.ubuntu.com/22.04/ubuntu-22.04.4-desktop-amd64.iso`）。
4. 设置虚拟机名称（例如 `VulnResearch`）和安装路径（建议使用 SSD，路径中不要有中文字符或空格）。
5. **磁盘容量**：建议至少 120 GB，选择 **Store virtual disk as a single file**（性能优于拆分为多个文件）。
6. 点击 **Customize Hardware**（自定义硬件）：
   - **Memory**：至少 4 GB（推荐 8 GB）；如果宿主机有 32 GB RAM，可分配 16 GB。
   - **Processors**：至少 4 核（推荐 8 核），勾选 **Virtualize Intel VT-x/EPT**。
   - **Network Adapter**：默认 NAT 模式即可，实验阶段无需桥接。
   - **CD/DVD**：确保已加载 Ubuntu 22.04 的 ISO 文件。
7. 点击 **Close** → **Finish**，虚拟机创建完成。

#### VirtualBox 创建步骤

1. 点击 **新建（New）**。
2. 名称随意填写（如 `vuln-research`），类型选 **Linux**，版本选 **Ubuntu (64-bit)**。
3. 内存分配 4~8 GB，处理器分配 4 核。
4. 虚拟硬盘选择 **VDI**，动态分配，容量 120 GB 以上。
5. 创建完成后，在 **设置 → 存储 → 光驱** 中加载 Ubuntu 22.04 ISO 文件。
6. 点击 **启动** 开始安装。

### 2.3.3 Ubuntu 22.04 安装过程

1. 虚拟机从 ISO 启动后，进入 Ubuntu 桌面。选择左侧栏的 **Install Ubuntu**。
2. **语言**：选择 **English**（避免路径编码问题，大多数安全工具默认英文路径）。
3. **键盘布局**：默认 English (US) 即可。
4. **安装类型**：选择 **Minimal installation**（取消勾选 "Install third-party software for graphics and Wi-Fi" 以避免安装不稳定的第三方驱动），勾选 **Download updates while installing Ubuntu**。
5. **安装类型**：选择 **Erase disk and install Ubuntu**（VMware/VirtualBox 分配的虚拟磁盘，不影响宿主机数据）。
6. **时区**：选择 Asia/Shanghai（或你所在的时区）。
7. **用户信息**：设置用户名（建议全小写英文，如 `vuln`）和密码。**不要勾选**"Log in automatically"，保持登录需要密码以保护研究环境安全。
8. 点击 **Install Now** 确认，开始安装。约 10~15 分钟后安装完成，提示重启时点击 **Restart Now**。

### 2.3.4 安装 VMware Tools / VirtualBox Guest Additions

安装完 Ubuntu 后，必须安装虚拟机增强工具以获得更好的性能（分辨率自适应、剪贴板共享、拖拽文件等）。

#### VMware Tools（适用于 VMware）

**方法一：使用 VMware 内置的"安装 VMware Tools"按钮（推荐）**

1. 在 VMware 虚拟机窗口顶部菜单，点击 **VM → Install VMware Tools**。
2. Ubuntu 桌面上会出现一个光盘图标 "VMware Tools"。
3. 打开终端（Ctrl+Alt+T），执行：

```bash
# 挂载光驱并复制安装包
sudo mkdir -p /mnt/cdrom
sudo mount /dev/cdrom /mnt/cdrom
cp /mnt/cdrom/VMwareTools*.tar.gz /tmp/
cd /tmp
tar -xzf VMwareTools*.tar.gz
cd vmware-tools-distrib

# 以 root 权限安装
sudo ./vmware-install.pl
```

安装过程中，所有选项均按回车接受默认配置。安装完成后，执行：

```bash
# 重启虚拟机使增强工具生效
sudo reboot
```

**方法二：使用 open-vm-tools（开源替代，推荐 Ubuntu 用户）**

open-vm-tools 是 VMware 官方维护的开源工具包，兼容性更好：

```bash
sudo apt update
sudo apt install -y open-vm-tools-desktop
sudo reboot
```

#### VirtualBox Guest Additions

```bash
# 安装依赖
sudo apt update
sudo apt install -y build-essential dkms linux-headers-$(uname -r)

# 在 VirtualBox 菜单中选择"设备 → 插入增强工具光盘镜像"
# 然后在虚拟机中执行：
sudo /media/$USER/VBox_GAs_*/autorun.sh
```

### 2.3.5 初始系统配置

安装完成后，执行以下初始化操作：

```bash
# 更新软件包列表和已安装软件
sudo apt update && sudo apt upgrade -y

# 安装基础开发工具链
sudo apt install -y build-essential git curl wget vim python3 python3-pip python3-venv

# 安装常用依赖库（后续编译工具需要）
sudo apt install -y libtool automake autoconf bison flex m4 zlib1g-dev libpixman-1-dev libssl-dev

# 设置静态 IP（可选，但推荐研究环境使用固定 IP 方便远程调试）
# 编辑 /etc/netplan/00-installer-config.yaml
```

设置固定 IP 示例（使用 NAT 模式）：

```bash
# 查看当前网络配置
ip addr

# 编辑网络配置
sudo vim /etc/netplan/00-installer-config.yaml
```

```yaml
network:
  version: 2
  renderer: networkd
  ethernets:
    ens33:  # 根据实际网卡名调整
      dhcp4: false
      addresses: [192.168.220.100/24]
      gateway4: 192.168.220.2
      nameservers:
        addresses: [8.8.8.8, 8.8.4.4]
```

```bash
sudo netplan apply
# 验证网络连通性
ping -c 3 www.google.com
```

> **注意**：研究环境应与外网隔离或仅允许必要的安全更新。研究人员常常需要处理恶意样本，过度联网会增加风险。建议在 NAT 模式下配置，仅允许特定端口的出站流量。

## 2.4 安装 IDA Pro

### 2.4.1 概述

IDA Pro（Interactive Disassembler Professional）是全球最强大的交互式反汇编和逆向工程工具。它支持 60+ 处理器架构和 20+ 文件格式，在漏洞研究领域几乎是必装工具。

IDA Pro 有两个主要版本：

| 版本 | 价格 | 功能 |
|------|------|------|
| IDA Free | 免费 | 支持 x86/x64 反汇编，功能受限 |
| IDA Pro (Commercial) | 昂贵（按年授权） | 全架构支持、Hex-Rays 反编译器、调试器、脚本支持 |

对于学习者，IDA Free 足以覆盖 x86/x64 架构的基础分析需求。

### 2.4.2 IDA Free 安装

**下载地址**：`https://hex-rays.com/ida-free/`

下载页面需要注册/登录账号（可用邮箱免费注册）。下载 Linux 64-bit 版本（`.run` 安装包）。

#### 安装步骤

```bash
# 假设文件下载到 ~/Downloads/
cd ~/Downloads/

# 给安装脚本添加执行权限
chmod +x idafree-9.0.240828-linux.run   # 文件名因版本而异

# 运行安装程序
sudo ./idafree-9.0.240828-linux.run
```

安装程序会引导你选择安装路径，默认为 `/opt/idafree-9.0/`。

```bash
# 启动 IDA Free
/opt/idafree-9.0/ida64
```

#### 桌面快捷方式配置

```bash
# 创建桌面启动器
cat << 'EOF' > ~/Desktop/IDA-Free.desktop
[Desktop Entry]
Version=1.0
Type=Application
Name=IDA Free
Comment=Interactive Disassembler Free
Exec=/opt/idafree-9.0/ida64
Icon=/opt/idafree-9.0/icons/ida.png
Terminal=false
StartupNotify=true
Categories=Development;ReverseEngineering;
EOF

chmod +x ~/Desktop/IDA-Free.desktop
```

### 2.4.3 IDA Pro Commercial 安装

如果你拥有商业许可证，可下载完整版：

**下载地址**：`https://hex-rays.com/ida-pro/`

```bash
cd ~/Downloads/
chmod +x ida-pro-9.0.xxx.run
sudo ./ida-pro-9.0.xxx.run
```

安装完成后，将许可证文件 `idagui.cfg`（或 `idaserver.cfg`）放入安装目录：

```bash
sudo cp ~/Downloads/idagui.cfg /opt/ida-9.0/
# 如果是网络许可证
sudo cp ~/Downloads/idaserver.cfg /opt/ida-9.0/
```

### 2.4.4 IDA Free 功能限制（重要）

IDA Free 与商业版存在以下差距，漏洞研究中需要了解：

| 功能 | IDA Free | IDA Commercial |
|------|----------|---------------|
| x86/x64 反汇编 | ✅ 完整 | ✅ 完整 |
| ARM/MIPS 等架构 | ❌ 不支持 | ✅ 支持 |
| Hex-Rays 反编译器 | ❌ 不支持 | ✅ 支持 |
| 远程调试 | ❌ 不支持 | ✅ 支持 |
| 脚本引擎（IDC/IDAPython） | ✅ 基础支持 | ✅ 完整支持 |
| 插件扩展 | ❌ 部分受限 | ✅ 完整支持 |
| 数据库管理 | ❌ 单文件 | ✅ 项目管理 |

> **实战提示**：对于 x86/x64 Linux ELF 二进制分析，IDA Free 完全够用。但遇到 ARM IoT 固件、MIPS 路由器二进制时，需要 IDA Commercial 或使用 Ghidra（免费，支持更多架构）。

## 2.5 安装 Ghidra

### 2.5.1 概述

Ghidra 是美国国家安全局（NSA）于 2019 年开源的逆向工程框架，提供了与 IDA Pro 类似的交互式反汇编、反编译和调试能力。其核心优势在于**完全免费**且**支持架构极为广泛**（包括所有 IDA Free 不支持的架构），并内置了强大的脚本自动化能力（Java/Python）。

### 2.5.2 系统要求

| 组件 | 最低要求 | 推荐 |
|------|---------|------|
| JDK | JDK 11+（Ghidra 10.x）/ JDK 17+（Ghidra 11.x） | JDK 17 LTS |
| 内存 | 4 GB | 8 GB+ |
| 磁盘 | 2 GB | SSD |
| 显示器 | 1280×720 | 1920×1080+ |

### 2.5.3 安装 OpenJDK 17

Ghidra 需要 Java 运行时环境。在 Ubuntu 22.04 上推荐使用 OpenJDK 17：

```bash
# 安装 OpenJDK 17
sudo apt install -y openjdk-17-jdk

# 验证 Java 版本
java -version
# 应显示：openjdk version "17.0.x"

# 验证 JAVA_HOME 环境变量
echo $JAVA_HOME
# 如果为空，设置它：
echo "export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64" >> ~/.bashrc
source ~/.bashrc
echo $JAVA_HOME
```

### 2.5.4 下载与安装 Ghidra

**下载地址**：`https://github.com/NationalSecurityAgency/ghidra/releases`

选择最新的 **ghidra_11.x_PUBLIC_xxxxxxxx.zip**（约 400 MB）下载。

```bash
cd ~/Downloads/

# 解压到 /opt/ 目录（避免路径含空格和特殊字符）
sudo unzip -q ghidra_11.1_PUBLIC_20240208.zip -d /opt/

# 进入安装目录
cd /opt/ghidra_11.1_PUBLIC/

# 验证可执行
./ghidraRun
```

首次运行会显示 Ghidra 启动画面（带 NSA Logo），加载完成后将打开项目窗口。

### 2.5.5 配置 Ghidra 使用 Python 3

Ghidra 自带 Jython（Java 实现的 Python 2），但大多数现代安全脚本使用 Python 3。Ghidra 11+ 内置了 CPython 3 支持（通过 GraalVM Python），旧版本需要手动配置。

```bash
# 检查 Ghidra 支持的 Python 环境
ls /opt/ghidra_11.1_PUBLIC/Ghidra/Support/

# 查看 launch.sh 支持的参数
./ghidraRun --help
```

Ghidra 的 Python 脚本编辑器中，可以通过顶部菜单 **Window → Python** 打开 Python 解释器。对于 Python 3 脚本，在脚本编辑器中选择 **Python 3 (Jython3/GraalPy)**。

### 2.5.6 Ghidra Server（可选）

Ghidra 支持协作模式，多人同时分析同一二进制：

```bash
# 启动 Ghidra Server
cd /opt/ghidra_11.1_PUBLIC/server/
./ghidraServer

# 配置文件位于：
# /opt/ghidra_11.1_PUBLIC/server/conf/ghidra.server
```

### 2.5.7 环境验证

```bash
# 无头模式分析（batch mode，用于脚本自动化）
/opt/ghidra_11.1_PUBLIC/support/analyzeHeadless \
  /tmp/ghidra_project \
  test_analysis \
  -import /bin/ls \
  -postScript InsecureCryptoDetector.java
```

这条命令会无头启动 Ghidra，创建项目，加载 `/bin/ls`，运行 `InsecureCryptoDetector.java` 脚本，最后输出分析结果。验证无误即表明 Ghidra 安装正确。

## 2.6 安装 AFL++（覆盖率引导 Fuzzer）

### 2.6.1 概述

AFL++（American Fuzzy Lop Plus Plus）是业界最流行的覆盖率引导模糊测试工具。它通过编译时插桩（instrumentation）追踪代码覆盖率，自动生成能够触发新代码路径的输入，从而高效地发现程序漏洞。AFL++ 是 AFL（Michał Zalecki 原版）的活跃维护分支，功能远超原版。

AFL++ 支持两种主要的插桩模式：

- **LLVM Mode（推荐）**：使用 LLVM/Clang 的 SanitizerCoverage 基础设施，性能最优，支持 QEMU 联合模糊（QEMU 模式）。
- **QEMU Mode**：对未提供源码的目标二进制进行模糊测试，通过动态二进制翻译（DBT）注入插桩代码。

### 2.6.2 安装依赖

```bash
# 更新并安装所有编译依赖
sudo apt update
sudo apt install -y \
    build-essential \
    git \
    python3-dev \
    automake \
    bison \
    flex \
    libtool \
    libc6-dev-i386 \
    llvm-dev \
    clang \
    llvm \
    llvm-14 \
    llvm-14-dev \
    clang-14 \
    lld-14 \
    gcc-multilib \
    g++-multilib
```

### 2.6.3 下载 AFL++ 源码


### 2.6.8 AFL++ 快速上手：第一次 Fuzz

下面用 AFL++ 对一个简单程序进行模糊测试，这是所有漏洞研究者必须完成的"Hello World"实验。

#### 步骤 1：编写目标程序

```bash
mkdir -p ~/fuzzing_tutorial
cd ~/fuzzing_tutorial

# 创建目标程序：有漏洞的简单 HTTP 解析器
cat << 'EOF' > target.c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>

// 模拟一个有漏洞的 HTTP Header 解析器
// 漏洞：strcpy 没有边界检查，可导致栈缓冲区溢出
void parse_http_header(const char *input, size_t len) {
    char buffer[128];  // 固定大小缓冲区
    int i = 0;

    // 简单状态机：提取 "Host: xxx" 中的主机名
    while (i < len && i < 256) {
        if (input[i] == 'H' && i + 4 < len &&
            strncmp(&input[i], "Host", 4) == 0) {
            i += 4;
            // 跳过冒号和空格
            while (i < len && (input[i] == ':' || input[i] == ' ')) i++;
            // 复制到缓冲区（漏洞点：没有长度检查！）
            int j = 0;
            while (i < len && input[i] != '\r' && input[i] != '\n' && j < 128) {
                buffer[j++] = input[i++];
            }
            buffer[j] = '\0';
            printf("[DEBUG] Host: %s\n", buffer);
        }
        i++;
    }
}

int main(int argc, char *argv[]) {
    if (argc < 2) {
        fprintf(stderr, "Usage: %s <input_file>\n", argv[0]);
        return 1;
    }

    FILE *f = fopen(argv[1], "rb");
    if (!f) {
        perror("fopen");
        return 1;
    }

    // 读取文件内容
    fseek(f, 0, SEEK_END);
    long fsize = ftell(f);
    fseek(f, 0, SEEK_SET);

    char *buf = malloc(fsize + 1);
    fread(buf, 1, fsize, f);
    buf[fsize] = '\0';

    parse_http_header(buf, fsize);

    free(buf);
    fclose(f);
    return 0;
}
EOF
```

#### 步骤 2：使用 AFL++ 插桩编译目标程序

```bash
# 使用afl-clang-fast 编译（自动注入覆盖率插桩）
# -g：保留调试信息
# -O0：关闭优化，避免编译器内联影响覆盖率
# 注意：必须使用 AFL++ 提供的编译器包装器
afl-clang-fast target.c -o target_fuzz -g -O0

# 验证二进制是否被插桩
file target_fuzz
# 应输出包含 "ELF 64-bit LSB shared object, x86-64, ... hybrid fuzzing instrumentation"

# 另一种验证方式：检查是否包含 AFL 特征字符串
strings target_fuzz | grep -i "AFL"
# 应看到 "__afl_maybe_log", "__afl_store" 等函数名
```

#### 步骤 3：创建初始语料库

```bash
# 创建输入目录和初始测试用例
mkdir -p seeds
echo -e "Host: example.com\r\n" > seeds/valid1.txt
echo -e "GET / HTTP/1.1\r\nHost: test.com\r\n" > seeds/valid2.txt
echo -e "Host: aa\r\n" > seeds/short.txt

# 验证目标程序能正常处理这些输入
./target_fuzz seeds/valid1.txt
# 应输出：[DEBUG] Host: example.com
```

#### 步骤 4：运行 AFL++ 模糊测试

```bash
# 创建 AFL++ 的输出目录
mkdir -p findings

# 启动模糊测试
# 使用 Screen 或 tmux（如果需要后台运行）
sudo apt install -y screen
screen -S fuzzing

afl-fuzz \
    -i seeds/ \
    -o findings/ \
    -x /usr/share/afl/dictionaries/http.dict \
    -- ./target_fuzz @@

# 参数说明：
#   -i seeds/          : 输入语料库目录
#   -o findings/       : 模糊测试输出目录（保存崩溃用例、覆盖率数据等）
#   -x                 : 可选的字典文件（提供协议关键字提示）
#   @@                 : AFL++ 会在 @@ 处替换为测试用例的临时文件路径
```

> **注意**：首次运行 AFL++ 时，如果检测到系统状态不安全（如未设置 `-fsanitize=address` 的库），会显示警告提示（红色）。忽略警告继续（按 `s` 跳过）。

AFL++ 启动后，你会看到一个彩色 TUI 界面，显示：
- **Overall Results**：总执行次数、每秒执行次数（ex/sec）、崩溃数
- **Cycle Progress**：当前 fuzzing 轮次、覆盖的唯一路径数
- **Map Coverage**：覆盖率统计

正常运行几秒到几分钟后，应能看到 **"overall results: X crashes"** 指示有崩溃被触发。

#### 步骤 5：分析崩溃结果

```bash
# 查看崩溃目录
ls -la findings/default/crashes/

# 查看具体的崩溃输入
cat findings/default/crashes/id:000000*

# 使用 AddressSanitizer 信息辅助调试
./target_fuzz findings/default/crashes/id:000000* 2>&1

# 用 GDB 分析崩溃
gdb -ex "run findings/default/crashes/id:000000*" \
    -ex "bt" -ex "quit" ./target_fuzz
```

在 GDB 中，你应该能看到 `strcpy` 写入超长字符串导致栈溢出，触发 `SIGSEGV`（段错误）或 `SIGABRT`（Aborted）。这正是 AFL++ 帮助我们发现的漏洞。

> **安全提示**：所有崩溃用例（crash inputs）可能包含实际恶意代码片段。在分析时，确保在隔离的虚拟机环境中操作，不要将崩溃用例复制到宿主机或联网环境。

## 2.8 安装 QEMU 用户态模拟器

### 2.8.1 概述

QEMU（Quick Emulator）是一款功能强大的开源机器模拟器和虚拟化工具。在漏洞研究中，我们主要使用 QEMU 的**用户态模拟模式（User-mode Emulation）**，它允许在 Linux x86_64 主机上直接运行其他架构（如 ARM、MIPS、RISC-V）的可执行文件，而无需完整的虚拟机。

典型使用场景：
- 分析 IoT 设备的 ARM/MIPS ELF 二进制文件
- 在 x86 主机上运行 MIPS 架构的漏洞样本
- 交叉编译后的程序在本地验证运行
- AFL++ QEMU 联合模式（已在前文 AFL++ 章节中配置）

### 2.8.2 安装 QEMU

#### 方法一：apt 快速安装（推荐用于 QEMU 用户态）

```bash

# 查看已安装的支持架构

# qemu-arm-static          (ARM)
# qemu-armeb-static        (ARM Big-Endian)
# qemu-mips-static         (MIPS)
# qemu-mipsel-static       (MIPS Little-Endian)
# qemu-ppc-static          (PowerPC)
# qemu-riscv64-static      (RISC-V 64-bit)
# qemu-x86_64-static       (x86_64)
# qemu-i386-static         (x86 32-bit)
```

#### 方法二：从源码编译安装（获取最新特性）


### 2.8.3 使用 QEMU 用户态模拟

#### 基本用法

```bash
# 查看可执行文件的架构
file /bin/ls
# 输出：ELF 64-bit LSB shared object, x86-64 ...

# 在 x86_64 主机上运行 x86_64 程序（直接运行，不需要 QEMU）
/bin/ls -la /tmp/

# 运行 ARM 架构的程序（跨架构）
qemu-arm /path/to/arm_binary
```

#### 使用 binfmt_misc 自动识别架构

binfmt_misc 是 Linux 内核的一个特性，允许系统自动根据 ELF 头信息选择合适的 QEMU 用户态模拟器来运行程序。配置后，你在终端中运行 ARM 二进制文件和运行本地 x86 二进制文件一样简单。

```bash
# 安装 binfmt-support（自动注册处理器格式）
sudo apt install -y binfmt-support

# 检查 binfmt_misc 是否已挂载
cat /proc/sys/fs/binfmt_misc/status
# 如果不是 "enabled"，手动挂载：
sudo mount -t binfmt_misc none /proc/sys/fs/binfmt_misc

# 注册 QEMU 各架构的格式处理器
# QEMU 提供了一个自动注册脚本
sudo ~/Downloads/qemu/configure --enable-linux-user  # 确保 configure 完成

# 使用 update-binfmts 安装所有用户态模拟支持
# 对于 apt 安装的 qemu-user：
sudo apt install -y qemu-user-binfmt

# 验证已注册的格式
cat /proc/sys/fs/binfmt_misc/qemu-arm
# 应显示：enabled

# 测试：用 QEMU 运行一个简单的 ARM 程序（假设有 ARM 交叉编译的 hello）
# 不需要手动指定 qemu-arm，binfmt_misc 会自动处理
./hello_arm  # 自动通过 qemu-arm 执行
```

#### 交叉编译示例：ARM 程序 → x86 主机验证

```bash

# 编写测试程序

#include <stdio.h>

    printf("Running on %s architecture!\n", ARCH);
    return 0;

# 交叉编译为 ARM32

# 在 x86_64 主机上用 QEMU 运行

# 输出：Running on arm architecture!

# 加上 -L 参数指定 ARM 动态链接库路径（如果有运行时依赖）

```

#### GDB 远程调试 QEMU 模拟的程序

## 2.10 章节总结

本章系统地完成了漏洞研究基础环境的搭建工作。核心要点回顾如下：

### 2.10.1 环境架构

```
宿主机 (Windows/macOS/Linux)
    └── VMware Workstation / VirtualBox
            └── Ubuntu 22.04 LTS 虚拟机
                    ├── IDA Free / Ghidra        → 静态逆向分析
                    ├── AFL++ (LLVM + QEMU)      → 模糊测试
                    ├── GDB + pwndbg             → 动态调试
                    └── QEMU User-mode           → 跨架构模拟
```

### 2.10.2 关键配置参数

| 配置项 | 推荐值 |
|--------|--------|
| 虚拟机内存 | ≥ 8 GB |
| 虚拟机 CPU | ≥ 4 核（勾选 VT-x/EPT） |
| 虚拟磁盘 | ≥ 120 GB SSD |
| AFL++ 编译模式 | LLVM Mode（优先）+ QEMU Mode（备选） |
| Ghidra JDK | OpenJDK 17 LTS |
| IDA Free | 仅支持 x86/x64，有架构限制 |
| QEMU | 安装多架构支持（arm/aarch64/mips/riscv64） |

### 2.10.3 常见陷阱

1. **Hyper-V 冲突**：Windows 宿主机开启 Hyper-V 会导致 VMware 无法运行 64-bit 虚拟机。解决方法是关闭 Hyper-V 或升级到 VMware 17+。
2. **磁盘空间不足**：AFL++ 模糊测试会生成大量语料文件（可达数百 GB），务必确保虚拟磁盘空间充足，建议分配 200 GB 以上。
3. **ASAN 性能**：用 AddressSanitizer（`-fsanitize=address`）编译的程序运行速度会慢 2~5 倍，但能检测出更多内存错误。在 Fuzzing 时必须启用。
4. **AFL++ forkserver 卡住**：在 WSL2 或部分虚拟机环境中，AFL++ 的 forkserver 可能无法正常工作。使用 `AFL_SKIP_CPUFREQ=1` 和 `AFL_FORKSRV_INIT_TMOUT=1000` 环境变量可以缓解。
5. **QEMU 动态链接**：运行跨架构程序时，如果遇到动态链接库缺失错误，使用 `-L` 参数指定库路径，或安装 `qemu-user-binfmt` 自动处理。
6. **IDA Free 无 GUI**：IDA Free 在 Linux 上没有原生 GUI，只能通过 X11 Forwarding 或 VNC 查看图形界面。Ghidra 在 Linux 上的 GUI 支持则原生良好。
